Hermes Agent：把"越用越聪明"做成有预算、可审计的工程系统

Nous Research 的开源 Agent 在 OpenRouter（第三方模型 API 聚合网关：统一接入各家大模型、按 token 用量计费，并按"经其路由的消耗量"发布应用用量排行）应用用量榜登顶：约 1.57 万亿 token（token 是大模型处理文本的计量单位），约为第二名 Claude Code 的两倍。它的差异化不在模型更强，而在把"从经验中学习"拆成了四层子系统——策展式持久记忆、渐进加载的技能、后台自我改进审查、全历史全文检索——每一层都自带容量预算、审批门控与安全扫描。

先给结论记忆不是堆得越多越好，而是"策展"出来的：字符上限逼迫 Agent 自己合并删除；后台审查在便宜模型上提炼经验；审批门控让"AI 写进你画像里的每一句话"都要过你的手。对做 Agent 系统的工程师，这套学习回路加治理的设计，比登顶数字本身更值得抄作业。

01 / Decision brief

TL;DR（太长不看）：一个把"自我改进"当第一等系统来设计的开源 Agent

01 / WHAT

发生了什么

Nous Research 的开源 Agent 项目 Hermes Agent（GitHub 仓库 NousResearch/hermes-agent，MIT 许可证）在 OpenRouter 应用用量榜（数据截至 2026-09-14）以约 1.57 万亿 token 居首，约为第二名 Claude Code（约 7140 亿）的两倍；仓库约 24.6 万 star。

02 / WHY

解决谁的问题

主流 Agent 每次会话从零开始，经验无法沉淀；人工维护的规则文件（如 CLAUDE.md）更新靠人。Hermes 把"学到什么、怎么存、何时用、谁批准"做成自动运转又可人工治理的子系统。

03 / HOW

核心机制

四层学习系统：MEMORY.md/USER.md 策展式记忆（硬容量上限）、SKILL.md 技能库（渐进式披露按需加载）、每轮结束后的后台自我改进审查（可路由到便宜模型）、SQLite 全文检索全部历史会话。

04 / SHIP

生产判断

个人助理与团队自动化场景当下可用（5 美元档 VPS——虚拟专用服务器，按月租用的云端小主机——即可运行，经 Telegram 等消息平台交互）；审批门控默认关闭，接到生产凭据域前必须显式打开；用量榜单名不等于用户量第一。

来源事实OpenRouter 排行页（数据截至 2026-09-14）与 GitHub 仓库页（数据截至 2026-09-16）显示上述用量与热度数据；记忆容量、审批门控、后台审查等机制描述均转写自官方文档（来源 02–04）。本文推断用量登顶与其"常驻网关"形态直接相关——持续在线、定时任务、多平台转发天然放大 token 消耗，榜单证明的是"运行量"而非"用户数"。
02 / Background

背景与问题：Agent 的下一个战场，是"经验能不能留下来"

过去两年，Agent（能自主调用工具、连续多步完成任务的 AI 程序）的能力边界由两样东西决定：模型有多聪明，工具有多齐全。2026 年这两样都在快速同质化——模型层各家互相追赶，工具层 MCP（Model Context Protocol，一个把外部能力以标准接口挂给模型的协议生态）让"能调多少 API"不再是壁垒。剩下的差异化变量是：这个 Agent 用了一个月之后，和第一天有什么不同。

A旧方式：经验留不下来

多数 Agent 每次会话从零开始。用户想留下点什么，主要靠两条路：人工规则文件——在仓库里手写 CLAUDE.md、AGENTS.md 这类说明文件，把"我们团队的约定"喂给模型，但内容全靠人更新；厂商托管的记忆——ChatGPT、Copilot 等产品的 Memory 功能能记住偏好，但记忆存在厂商服务器、不可导出不可审计、换模型即失效。两条路的共同问题：学习这个动作本身，要么由人完成，要么被厂商锁定。

  • 规则文件不会自己生长：犯过的错、摸索出的流程，下次会话照犯照摸。
  • 托管记忆是黑盒：用户看不到、也管不了 AI 记了自己什么。
  • 长会话的隐性成本：对话越长，压缩越频繁，费用随历史线性上涨。

B为什么此时出现 Hermes Agent

同期信号密集：Hugging Face 论文页上 Prime Agent（自我改进 harness——harness 指包裹模型、供其运行并沉淀经验的执行环境——约 2.08 万 star）、NeoHorse-1（414 票，递归自我改进）、Microsoft SkillOpt（把技能当外部状态优化的文本空间优化器）等工作连续上榜；OpenAI 与 Anthropic 各自经营 skills 目录；记忆中间件 Mem0 论文长期位居引用榜。本文推断，行业共识正在形成："会学习"应当成为 Agent 的系统属性，而不是提示词技巧。Hermes Agent 把这件事推得最远——它直接自称"the self-improving AI agent"（自我改进的 AI Agent），并把学习循环写进了产品标语"the agent that grows with you"（与你一起成长的 Agent）。

判断边界：本文不评测"它学得准不准"——那需要长期实测；本文回答的是"它把学习做成了什么样的系统，这个设计里哪些是可迁移的"。全部能力描述来自官方文档与仓库页面，未包含作者实测数据。

03 / Mechanism

核心原理：四层学习系统，每层都有预算、门控和扫描

Hermes Agent 对"学习"的拆解不是一句提示词里的"请记住用户的偏好"，而是四层职责清晰的子系统：陈述性记忆（记住事实）、程序性技能（记住怎么做）、后台审查（决定值得记什么）、历史检索（记不全的查得到）。它运行在自有主目录（~/.hermes/）中，一个网关进程同时接入 Telegram、Discord、Slack、WhatsApp、Signal 等消息平台与命令行。

01 / START会话开始：注入冻结快照MEMORY.md 与 USER.md 的当前内容在会话开始时一次性注入 system prompt（系统提示词，每次对话固定开头的指令块），会话中途不再变化——以保住前缀缓存（prefix cache：请求开头不变时，服务商可复用已算好的部分，降费提速）。
02 / WORK工作中：技能按需加载技能目录只占约 3k token 的索引位；用到哪个技能，才加载哪份全文，进一步展开参考文件。
03 / BOUNDARY会话边界：/new 开新会话记忆的价值在旧会话结束时兑现：新会话重新读取更新后的记忆，上下文从零开始、保持便宜。
04 / REVIEW后台审查：回放提炼每轮结束后派生一个后台分支，回放对话，把反复出现的纠正与可复用流程提炼成记忆条目或技能补丁。
05 / GOVERN治理：扫描与审批写入前扫描注入与外泄模式；开启审批门控后，一切记忆与技能写入先暂存，经 /memory pending 逐条批准或拒绝。

01陈述性记忆：策展，而非堆砌

两个文件构成持久记忆：MEMORY.md（Agent 的个人笔记——环境事实、项目约定、踩过的坑）上限 2200 字符（约合 800 token）；USER.md（用户画像——偏好、沟通风格）上限 1375 字符（约 500 token）。这个上限是硬约束：写入超限时工具直接报错，把现有条目列表回显给 Agent，要求它在同一回合内先合并（replace）或删除（remove）旧条目，腾出空间再重试——系统不做自动压缩。官方文档明确了这样设计的动机：记忆要"聚焦"，被迫取舍本身就是学习的一部分。系统提示词中还会显示容量水位（如"67% — 1474/2200 chars"），让 Agent 始终知道自己还剩多少"记性"。

02程序性技能：渐进式披露

技能（Skills）是按需加载的操作手册，每个技能是一个 SKILL.md 文件加可选的参考目录，兼容 agentskills.io 开放标准。加载分三级：第 0 级技能索引（名称+描述，整体约 3k token）常驻；第 1 级按需读入某个技能全文；第 2 级再按需读参考文件。Agent 通过 skill_manage 工具维护自己的技能库：闯出一条多步流程、踩坑后找到正确路径、被用户纠正做法时，就把经验写成技能。文档把两者的分工讲得很清楚：记忆存"应始终在场的小事实"，技能存"只在相关时才加载的长流程"。

03后台自我改进审查：学习的自动化引擎

每轮对话结束后，Hermes 派生一个后台分支（fork）回放整段对话，判断有没有值得留下的东西：反复的纠正提炼成记忆条目，可复用的工作流提炼成技能补丁。三个工程细节值得注意：成本路由——审查可配置到更便宜的模型上运行，此时改用对话摘要（digest）重放，官方基准约为在主模型上运行成本的 1/3 至 1/5；本地推理的谦让——审查若占用本地 GPU 会阻塞下一次提问，因此在托管本地模型上默认延迟到机器空闲时执行；双门控——memory.write_approval 与 skills.write_approval 打开后，来自前台对话与后台审查的一切写入都会先暂存（staged），经 /memory pending、/skills pending 逐条审阅后批准或拒绝。官方称这套设计为"consent-aware learning loop"（知情的、经同意的学习循环）。

04历史检索：记不全的，查得到

记忆容量有上限，但全部会话原文都存进本地 SQLite 数据库（~/.hermes/state.db），用 FTS5（SQLite 的全文检索扩展）建索引。Agent 用 session_search 工具检索过往对话：官方文档给出的量级是检索约 20 毫秒、滚动浏览约 1 毫秒，且不消耗任何模型 token——这是"上周我们讨论过 X 吗"这类问题的免费回答通道。它与记忆的分工：记忆约 1300 token 固定注入每个会话、承载关键事实；检索零成本、承载无限历史。两者合起来，才是完整的"长期记忆"。

一个反直觉的设计权衡：学习循环依赖"会话边界"。在消息平台上，一段聊天被刻意设计为跨重启的连续会话，可以数周不中断——方便，但后台记忆更新因冻结快照而对进行中的会话不可见，"遗忘→从记忆回忆→检索历史"的循环几乎不会触发，且上下文压缩要在一个越来越长的历史上反复运行、越来越贵。官方文档因此给出明确建议：在任务完成、话题切换、一天开始时主动 /new。会话越连续，Agent 越"失忆"；边界越清晰，Agent 越聪明。这与直觉相反——按本文分析，这正是这套系统成本结构的关键。

04 / What changed

真正的创新在哪里：把"自我改进"从行为变成协议

01学习是系统属性，不是提示词技巧

多数产品的"记忆"是一层中间件：捕获对话、抽取事实、检索注入。Hermes 的差异在于让 Agent 自己持有写权限（memory 与 skill_manage 是模型可调用的工具），同时给这个写权限配上完整治理——容量预算、内容扫描（记忆写入前检测提示词注入——prompt injection，把恶意指令藏进内容、诱导模型执行的攻击——以及凭据外泄与不可见 Unicode 字符模式）、暂存审批、可视化修剪（/journey 命令把学到的技能与记忆画成时间线，逐条可删可改）。在公开产品中，如此完整的自我改进治理面尚属少见（本文判断）。

02"学到什么"与"写下什么"被显式分离

学习动作拆成两段：判断（后台审查回放对话、提炼候选）与落笔（经门控写入记忆或技能）。两段之间是人可以介入的审查位。这正是自我改进类系统最难的一环——不是让 AI 学得快，而是让错误的学不被固化。小模型容易把一次巧合当规律、把用户的情绪当偏好写进画像；审批门控把这个风险从"事后发现"变成"事前拦截"。

03记忆经济学被精确到 token

每个数字都有据可查：记忆注入固定约 1300 token；技能索引约 3k token；历史检索零 token、20 毫秒；后台审查路由到便宜模型，可把这部分成本降至主模型运行成本的约 1/3 至 1/5；冻结快照保住前缀缓存。"记忆"在这套设计里不是玄学，是一张有预算的资产负债表。

04开放生态位：可换模型、可迁移、可扩展

模型无关——通过 Nous Portal（官方订阅网关，300 余个模型）、OpenRouter、OpenAI 或自建端点接入，hermes model 一条命令切换；技能生态八源并行——官方目录、skills.sh（Vercel 运营的技能目录）、站点自述文件（well-known）机制、GitHub 直装（默认收录 openai/skills、anthropics/skills、huggingface/skills、NVIDIA/skills 四个官方仓库）、ClawHub、LobeHub、browse.sh 与任意 URL，全部经安全扫描，并可选挂 NVIDIA SkillEvaluator 做第二道咨询性扫描；从另一个开源个人 Agent 项目 OpenClaw 提供一键迁移（hermes claw migrate），连人格文件 SOUL.md、记忆、技能、密钥都能搬走。

06 / Engineering

工程化视角：三个生产问题

问题一：今天就能用在生产里的是什么？

个人与团队的常驻助理 + 无人值守自动化。5 美元档 VPS 即可运行；一个网关进程同时在线 Telegram、Discord 等多个平台；内置 cron（沿用至今的 Unix 定时任务机制）调度器用自然语言定义"每天早上汇总新闻""每周审计一次依赖"这类任务，按计划送达任意平台。团队场景可把 skills.create_dir 指向一个 Git 仓库，让 Agent 创造的技能自动进入版本管理与代码评审。多步重复任务还能写成 Python 脚本经 RPC（远程过程调用，像调用本地函数一样使用远端功能）调用工具，把长流程折叠成零上下文成本的回合。

问题二：什么时候不该用它？

要求行为确定、可复现的场景慎用。自我改进意味着行为会漂移：今天跑通的流程，后台审查改写技能后明天可能不同。两个前置动作：接入生产凭据前打开两个审批门控（默认是关闭的），把一切写入置于人工审阅之下；对"每一步必须可审计"的流程，用 auxiliary.background_review.enabled: false 关闭自动学习，仅保留人工 /refine。另外官方文档明确警告：不要让两个 Agent 进程指向同一个主目录——两个写入者会互相污染记忆状态。

问题三：成本结构长什么样？

四块：基础设施——低至 5 美元 VPS；七种执行后端里的 Modal、Daytona 提供"闲时休眠"的按需计费，空闲近乎零成本；模型调用——主要变动成本，后台审查路由到便宜模型，可把这部分成本降至主模型运行成本的约 1/3 至 1/5，本地模型则把审查延迟到 GPU 空闲；记忆固定开销——每会话约 1300 token 注入，冻结快照设计保住前缀缓存折扣；会话管理——消息平台上的连续会话若数周不 /new，压缩成本会随历史增长反复累积，这是最容易被忽视的一项。

部署边界提示

官方对 Windows 提供原生 PowerShell 安装（自带隔离的便携 Git Bash 与 uv 包管理器，不污染系统环境），并诚实写明了杀毒软件误报 uv.exe 的验证与白名单步骤——这类细节是判断一个开源项目工程成熟度的好信号。安全面：记忆写入前的注入/外泄模式扫描、技能安装的强制扫描加咨询性二次扫描、项目级技能需显式 trust，构成了纵深防御的雏形；但 --force 可越过"警告"级拦截，说明最终防线仍是运维者自己。

07 / Risks

局限与风险：登顶数字之外必须看清的事

高

用量第一不等于用户第一

榜单统计的是经 OpenRouter 路由的 token 消耗量。Hermes 的形态——常驻网关、定时任务、多平台长会话——天然放大单用户消耗。1.57 万亿 token 证明"它在真实大规模运行"，不能直接推出"它是最受欢迎的 Agent"。本文推断编码类客户端的单用户用量远低于常驻助理。

高

审批门控默认关闭

"自由写入"是出厂默认。这意味着多数用户的后台审查在无人监督下持续改写记忆与技能。错误假设一旦写入 USER.md（用户画像），会在之后每个会话的 system prompt 里反复生效——画像污染是自我改进系统特有的复合风险。开箱即用与安全默认之间，Hermes 选择了前者。

中

学习质量依赖审查模型

官方未公布"审查提炼准确率"的系统性评测；为省钱把审查路由到小模型时，误学概率上升（文档也建议小模型用户开启写入审批）。学到错误经验的 Agent 会在错误方向上持续自我强化——反例验证（构造已知应拦截的错误学习样本）目前完全依赖用户自己。

中

供应链面在快速扩张

八条技能来源（其中 ClawHub、LobeHub 为无人工审核的社区市场）意味着攻击面同步扩张。扫描体系（强制扫描+SkillEvaluator 咨询扫描+dangerous 不可强制覆盖）设计认真，但 PII（个人身份信息）类发现被定位为"仅供参考"、部分拦截可被 --force 越过。项目级技能随 git pull 变化的信任缝隙，靠内容哈希扫描缓存来弥补。

中

画像数据的隐私面

USER.md 存的是用户行为画像，且经网关同步到 Telegram、Discord 等第三方平台。数据在本地主目录（这一点优于托管方案），但平台链路上的暴露面需要使用者自行评估；write_approval 与 /journey 修剪是仅有的治理工具。

中

反直觉的运维要求

学习循环依赖用户主动创造会话边界。多数用户不知道"长聊天会阻止 Agent 学习"这件事——产品把成本与学习效果的最大杠杆，放在了一个用户最不容易意识到的地方。

安全结论：把自我改进系统接入生产域的正确顺序是：先开两个审批门控，再接入凭据，最后才放定时任务。在通过你自己的错误学习样本验证之前，不要假设后台审查"学得对"。

08 / Outlook

未来方向：学习闭环的尽头是训练数据

技能互操作：agentskills.io 成行业公约？

同一份 SKILL.md 规范，Hermes 官方声明兼容（见来源 04）；OpenAI 与 Anthropic 各自经营以 SKILL.md 为载体的官方技能目录（见来源 04 的 GitHub 直装来源清单），Vercel 运营 skills.sh 目录。当"技能"成为跨 Agent 通用资产，写一次技能处处可用的网络效应会把标准固化——本文推断，2026 年内 SKILL.md 的地位大概率接近当年 Dockerfile 之于容器。

单 Agent 的经验，如何变成模型的能力

Hermes 仓库明示了研究出口：批量轨迹生成（batch trajectory generation）与轨迹压缩（trajectory compression），用于训练下一代工具调用模型。这条路径值得所有 Agent 团队注意——运行中沉淀的高质量"任务-尝试-修正-成功"轨迹，正是后训练（post-training）最贵的数据。学习闭环的终点不是更聪明的个体 Agent，而是把众多个体的经验蒸馏进模型本身。

记忆治理将成为标配功能

同期 Anthropic 发布 containment（遏制）工程文章、各厂商密集讨论 AI 安全标准组织（AIbase 报道），行业对"AI 自主行为"的治理共识在收敛。本文推断：水位显示、暂存审批、逐条修剪、写入扫描这套"记忆治理四件套"，会从 Hermes 的差异化特性变成用户对一切记忆功能的默认期望。

商业闭环：网关+订阅

Nous Portal 把 300 余个模型与搜索、图像、语音、云浏览器等工具网关打包进单一订阅，本文推断其商业逻辑与用量登顶互为因果：低门槛入口带来运行量，运行量反哺订阅收入。开源主体+托管增值的组合，正在成为独立 AI 实验室的标准生存结构。

09 / Takeaways

工程师可以借鉴什么

给记忆设预算，而不是给记忆加容量

Hermes 最反常识的一招是"记性小"：2200 字符上限加满载报错，逼 Agent 在写入前合并、删除、取舍。堆容量只会让记忆变成没人读的垃圾抽屉；设预算才会让留下来的每一条值钱。你自己的 Agent 系统里，记忆有没有预算？

把"学到什么"和"写下什么"分开，中间放审批

判断与落笔分离，学习流水线才有可插入的人工审查位。哪怕你的系统没有后台审查，也值得预留 staged writes（暂存写入）的接口——今天暂存的是记忆条目，明天可能就是会改动生产配置的技能。

冻结快照 + 会话边界，是记忆的经济学基础

记忆注入只在会话开始时发生、中途不变，保住前缀缓存；会话边界让每段工作从便宜的短上下文开始，学习循环（遗忘→回忆→检索）才有机会运转。长会话看似连续高效，实际同时牺牲了费用与学习——这个权衡值得写进每一个长任务的运维手册。

检索代替堆积：让历史零成本可查

FTS5 全文检索约 20 毫秒、零 token 成本，让 Agent 不必把一切都塞进上下文。判断标准很简单：这条信息是"每个回合都要在场"（进记忆），还是"偶尔需要查证"（进检索层）？绝大多数"记忆需求"其实是检索需求（本文判断，非统计结论）。

本文判断如果你正在搭 Agent 系统，Hermes 的记忆与技能文档比它的排行榜数字更值得精读——四层设计里每一条容量数字与门控开关都是可以直接抄走的工程决策；如果你只是选一个常驻个人助理，先打开审批门控再交给它凭据。
