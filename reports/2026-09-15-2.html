DeepSeek Harness：当 Agent 循环本身也成为插件

深度求索（DeepSeek）把自家 Agent 框架做成了一棵插件树：模型适配器、工具注册表、会话日志乃至默认 Agent 循环，都可以从配置中整件替换，不必改动任何核心源码。支撑这套设计的 Cordis 框架，来自一篇 92 页的编程语言论文。

先给结论它把自己定位成平台底座。生产接入需要等待稳定接口与安全审计；“注册即可逆、模型可见即可回放”这两条设计纪律，对做 Agent 系统的团队有直接参考价值。

01 / Decision brief

TL;DR（太长不看）：一个把“可替换性”推向极端的开源 Agent 框架

01 / WHAT

做了什么

深度求索开源 Agent 框架 DeepSeek Harness（命令名 dsh），TypeScript 编写、MIT 许可证，一条命令 npx @deepseek-ai/dsh web（npx 是 Node.js 的包执行器）即可启动本地 Web 界面。

02 / WHY

解决谁的问题

主流 Harness 的循环、模型接入、沙箱、审批大多内置在主体里，深度定制只能分叉源码。dsh 把这些部件全部拆成可从配置替换的插件。

03 / HOW

核心机制

底层 Cordis 框架让每个组件注册时自带撤销、声明依赖后自动启停；上层用 profile（组合方式）与 bundle（分发单位）分层拼装。

04 / SHIP

生产判断

官方定位是开发者预览：明言未来有破坏兼容性的变更、尚未做安全审计。适合隔离环境试用与架构学习；生产接入要等版本稳定并自建插件审查。

来源事实GitHub 仓库页面（2026-09-15 数据）显示约 22.5 万 star、约 2.7 万 fork；OpenRouter 应用消费榜（数据截至 2026-09-15）DeepSeek Harness 新上榜，token 消耗约 1380 亿（来源 01、06）。本文推断模型厂商亲自下场做 Harness，商业动机是把 API 调用与开发生态留在自家模型周边。
02 / Background

背景与问题：Harness 的能力边界，正在从“内置”走向“插件”

大语言模型（LLM，Large Language Model）本身只会生成文本。让它能读文件、执行命令、连续多步完成任务的，是包裹在模型外层的那套执行环境，行业称为 harness（本义是“挽具”，即套在马身上让马力可被使用的装备）。它负责组装上下文、登记工具、执行命令、把结果喂回模型，并管理会话、权限与审批。

A能力内置的代价

当前主流 Harness 的关键部件大多焊死在主体里：Claude Code 的循环、权限系统与模型接入运行在闭源主体内，官方扩展机制是技能与插件体系（其更新日志显示 2.1.269 版本新增了 claude plugin eval 插件评测命令）；开源编码客户端（如 OpenRouter 同榜的 Cline、Kilo Code）提供源码与配置项，深度修改行为的主要路径仍是维护源码分叉，截至发稿其公开文档尚未提供整件替换 Agent 循环的机制。

  • 企业想换一个沙箱实现或审批策略，等价于改内核。
  • 第三方想给循环加拦截逻辑，只能依赖官方预留的口子。
  • 能力演进节奏由厂商单方面决定。

B为什么此时出现 dsh

2026 年 9 月，“插件化”在同一周内密集出现：GitHub Trending 周榜同时出现 openai/plugins 与 openai/skills 两个仓库；Ollama 在 8 月 21 日发布的 v0.33.0 中专门为 DeepSeek Harness 启动器做了兼容修复；学术侧 Hugging Face 论文页同期出现 Prime Agent、NeoHorse-1、Show-Harness 等以 harness 命名的工作；深度求索同周还开源了 V4.1 Flash 模型，模型与 Harness 两侧动作在同一周叠加。能力边界正在从内置功能转向插件生态，dsh 是把这个方向推到极致的样本。

判断边界：star 与榜单数据仅证明关注度；本文的生产判断全部标为“本文推断”。

03 / Mechanism

核心原理：让“注册”自带撤销，让“依赖”自动响应

dsh 的底座是 Cordis 框架，其设计论文《A Programming Paradigm for Spatiotemporal Composability》（时空可组合性的编程范式）由北京大学与深度求索的研究者于 2026 年 8 月 26 日提交到 arXiv（编号 2608.25512，92 页，属编程语言方向）。论文把“动态组合软件组件”的难题拆成正交的两维，并分别给出运行时机制。

01时间维：可逆效果

传统插件系统里，“注册”是一次留下全局副作用的动作，卸载往往卸不干净。Cordis 要求组件对共享上下文的每一次变换都携带一个逆操作，由运行时统一持有；组件卸载时按逆操作回退，系统回到装载前的状态。论文称这一性质为时间可组合性：完全撤销一个组件的全部副作用。

直观类比：普通插件像在墙上钉钉子，拔掉后留下孔；Cordis 的插件自带“修复墙面”的义务，拔掉后墙面复原。

02空间维：反应式余效应

组件在装载时声明自己依赖上下文中的哪些能力（论文称为余效应规格）。运行时把每一次上下文变化对照规格分类，自动驱动该组件激活或停用。这一性质称为空间可组合性：声明式地管理组件间依赖。

直观类比：房间里的每个电器都声明自己需要什么线路；改线路时不必全屋排查，只有声明依赖它的设备会自动响应。

论文进一步把效果上下文与余效应上下文统一成单一上下文类型，所有组件的效果与依赖都经由它中介，作者称之为“上下文范式”。由此得到的结论是：不同组件的效果可以交错执行而互不干扰。Cordis 就是这套理论的工程实现：提供效果追踪与余效应求解的核心库，以及带配置调和与热模块替换的声明式组件装载器。在 dsh 的架构文档里，这句话被落成产品原则——“没有可打补丁的特权核心（no privileged core），你通过在其他插件旁边挂载一个插件来扩展 dsh，注册即效果，插件卸载时随之回退”。

01 / LAUNCHCLI 指定 profile如 dsh web；模板有 web、headless、sdk、sdk-minimal 与 acp（Agent Client Protocol，面向自动化客户端的服务器形态协议）五种。
02 / BASE装载共享层 dsh-base模型适配器、工具、持久化、沙箱与审批策略、设置、凭据、遥测。
03 / APP叠加应用 bundleweb-app 加浏览器界面；headless 加一次性运行器；sdk-app 加 JSON-RPC（一种以 JSON 文本编码的远程调用协议）服务器；acp-app 加自动化服务。
04 / PATCH逐层补丁profile 级 cordis.patch.yml，再 home 级，再 --patch 覆盖；补丁按行 ID 定位、替换或插入配置行。
05 / TREE得到插件树dsh --dump-config 可打印整棵树；树中任意一行都可被你自己的补丁替换。
# 示意：以下命令与配置树转写自官方架构文档，非本文实测输出
# 启动 Web 界面（默认 127.0.0.1:3080，自动打开浏览器）
npx @deepseek-ai/dsh web

# 打印 web profile 实际装载的插件树；任何一行都可被补丁替换
dsh --profile web --dump-config

# dsh-base 层中，连 Agent 循环也只是普通插件
core/agent-loop  -->  ctx.agentLoop   # 默认循环驱动器，可整件替换
core/session     -->  ctx.sessions    # 只追加的会话事件日志
core/tools       -->  ctx.tools       # 带作用域的工具注册表与受保护执行管道
llm/llm          -->  ctx.llm         # 模型适配器缝隙

三类事件域，决定扩展点选型

架构文档把事件分为三个域：会话事件是追加进日志的持久事实，需要在重载后存活时用它；Agent 事件（agent/*）携带进行中的工作，用于观察或拦截在途请求，其中多数是瀑布型（类似 Web 框架的中间件链，前一个处理完才轮到下一个）——监听器必须调用 next() 才能继续；能力事件（fs/*、tools/*、telemetry/*）把策略和适配器挂到缝隙上，不必导入循环本身。选扩展点时先问：这个事实需要持久，还是只关乎运行中的这一步？

会话日志是模型所见上下文的唯一来源

一个 step（步）是一次模型请求加它调用的工具；一个 turn（轮）是零或多步。架构文档的原话是“模型可见即可从日志重建（model-visible means logged）”，并有运行时不变量断言。任何到达模型请求的内容都必须能从会话日志重构；deriveMessages() 从日志投影出模型历史，分叉、恢复、迁移全部从日志派生。日志格式自带代际与迁移链：每个迁移包只负责一个 vN 到 vN+1 的步骤，已提交的代际路径永不改名或删除。

一个容易被低估的设计：文件系统与子进程两个提供者共享同一个“执行世界”。把执行世界指向一个远程沙箱时，Bash、伪终端（PTY，Pseudo Terminal）、语言服务器协议（LSP，Language Server Protocol）工具会一起迁移，不产生提供者分叉。换执行环境从“改造代码”变成“改一行配置”。

04 / What changed

真正的创新在哪里：把“可替换”从接口承诺变成架构事实

01循环本身是插件

多数系统把 Agent 循环写死在主体里、再对外开插件口。dsh 的默认循环（core/agent-loop）只是插件树上的普通一员：连模型适配器、工具注册表、会话日志、Agent 循环本身都在可替换清单上，且每件都从配置层替换，不动源码。

这意味着把默认循环换成带合规拦截的自研循环，可以作为一项常规的企业级需求来规划。

02注册即效果，卸载即回退

所有注册都是携带逆操作的效果。这把“给运行中的 Agent 增减能力”从重启级操作变成运行时操作：web profile 默认支持补丁实时重载，改配置不需要重建世界。对长时间运行的 Agent 而言，能力变更的可逆性直接决定回滚成本。

03分发即分层

bundle 是“配置行加代码”的分发格式，在自身 package.json 的 dsh 字段里声明。关键性质是：下层 bundle 插入的任何内容，仍可被上层补丁逐行覆写。第三方发行版因此不需要 fork 核心就能改变默认行为，且改动可按行 ID 审计——定制以可单独审查的差异文件的形式存在。

04论文先行于工程

在工程框架落地前，其形式化基础先以一篇编程语言论文发表：把效果（effect，指程序对外界产生的副作用）与余效应（coeffect，指程序对运行环境的依赖）两个编程语言概念提升为运行时机制，并给出元理论——可逆效果与反应式余效应的组合，能把时空可组合性从单组件推广到整棵交错组件树。工业开源项目附带论文级别的理论文档，这一做法在开源生态中并不多见（本文推断）。

来源事实以上四点分别对应官方架构文档的“无特权核心”章节、Cordis 章节、profile 与 bundle 章节，以及 arXiv:2608.25512 的摘要（来源 03、05）。本文推断元理论的实际意义，是给“插件可安全热插拔”提供了可证明的边界。

06 / Production

工程化视角：从 npx 到生产之间的六个环节

“能跑起来”只是开发者预览的起点。生产系统要回答的是：版本会不会突然不兼容、插件谁来审计、沙箱靠不靠得住、日志会不会泄密、替换一个部件后怎么证明行为没退化。

版本锁定与变更跟踪

官方明言“未来将出现破坏兼容性的变更”。接入方应锁定精确版本、订阅版本说明，并在隔离环境中先验证每次升级；每次升级都应作为一次回归测试事件对待。

沙箱独立成界，不指望框架自保

官方 SAFETY 文档写得直白：项目尚未接受安全审计、不得视为可用于生产；沙箱、审批与权限控制能降低风险但不保证隔离，不要把它当作不可信工作负载的唯一安全控制。生产部署应叠加一次性虚拟机或容器、最小权限与文件备份，这正是 Anthropic 工程团队在 2026 年 5 月发表的遏制实践文章反复强调的原则：环境层遏制优先于模型层自觉。

插件供应链审查

dsh 可以加载第三方插件并访问开放给它的网络、进程、凭据与文件。企业需要自建插件准入流程：来源与作者核验、代码审计、权限最小化声明。dsh-plugin 话题目前是社区自发挂载，尚未出现市场级的签名或权限治理机制。

把会话日志纳入审计面

“模型可见即可回放”意味着日志天然是完整的行为审计材料，但也意味着它包含全部业务上下文与工具结果。接入留存、脱敏、访问控制与保留期限策略，是使用 dsh 前的必修课。

替换件验证矩阵

一切皆插件意味着每个部件都可换，也意味着每次替换都是一次行为变更。为高频替换件（模型适配器、沙箱后端、审批策略、循环本身）建立成对回归：同一任务集上对比任务成功率、工具调用正确率与上下文一致性，替换前后各跑一遍。

观测先行

能力事件域允许把遥测与策略挂到 telemetry/* 等缝隙上而不侵入循环。迁移期最有价值的能力不是功能而是可观测性：先接遥测与追踪，再谈替换。

成本与延迟插件树装载时间、每轮请求数与 token 成本、补丁热重载影响、遥测开销。
可靠性与安全插件卸载后的状态干净度、审批拦截率、日志敏感内容扫描命中、插件漏洞响应时效。

从 Demo 到生产，主要差距集中在四处：接口稳定性、安全审计、插件治理、替换件回归验证。推荐接入顺序：学习期（--dump-config 读树、写不侵入循环的插件）→ 试用期（一次性虚拟机、低风险任务、遥测先行）→ 灰度期（锁版本、建回归集、立插件审查流程）→ 生产期（等待官方稳定接口声明与安全审计后再扩大范围）。

07 / Limits

局限与风险：可组合性不是免费午餐

高

开发者预览，破坏性变更在途

README 明言“未来将出现破坏兼容性的变更”。今天写的插件与补丁，没有任何接口稳定承诺。任何基于 dsh 的投入都要按“随时需要返工”定价。

高

未做安全审计

SAFETY 文档明确：项目尚未接受安全审计，不得视为安全或可用于生产的软件；沙箱与审批降低风险但不保证隔离。它自己不提供“不可信工作负载的唯一安全边界”。

高

插件供应链无治理

第三方插件可访问开放给项目的网络、进程、凭据与文件；发现机制目前是 GitHub 话题自发挂载，尚未见签名、权限声明或市场审核机制。Anthropic 在 2026 年 5 月的遏制实践文章中复盘过同类风险：仓库中带毒的 .claude/settings.json 钩子文件，会在用户确认信任该目录之前随项目启动自动执行。

中

一切皆插件的间接层成本

调试要跨插件边界追事件流，性能开销没有官方基准：仓库的 BENCHMARK 文档只指向 Python SDK 指南，未给公开数字。插件化越彻底，理解一次调用链所需的心智模型越贵。

中

热度不等于采用

约 22.5 万 star 证明关注度，OpenRouter 榜单约 1380 亿 token 显示经其路由的初步用量；尚无公开的生产部署案例研究。两者都不是生产就绪的证据。

中

单一主体治理

Cordis 与 dsh 的接口演进节奏都由深度求索主导。生态成型后，“换 harness 不换模型”与“换模型不换 harness”两个方向的锁定效应都会出现，宜提前评估退出成本。

安全结论：把 dsh 部署在专用环境并只授予最小权限，是官方文档明示的前置条件；在其通过独立安全审计之前，任何把它接入生产凭据域的方案都需要自证隔离有效性。

08 / Outlook

未来方向：从开发者预览到生态位

生态：从话题到市场

官方已铺好社区地基：dsh-plugin 话题便于插件被发现，企微群与 GitHub Discussions 承接反馈，Ollama 桌面端在 8 月已把 dsh 启动器纳入其应用并做兼容修复。本文推断，下一阶段大概率出现插件市场与签名、权限模型——这是任何插件生态走向生产的必经之路。

产品：多形态分发

架构文档披露了明确的分发矩阵：Electron 桌面应用（基于 Chromium 网页引擎与 Node.js 运行时的跨平台桌面应用框架）把精确版本的 dsh 运行时打包进签名资源、通过私有协议通信且不开回环端口；Python SDK 把 dsh 命令行打包为平台安装包；ACP profile 面向自动化；webhook 面向外部事件接入。框架正同时覆盖交互、无头、嵌入式三种形态。

协作：Agent Teams 原语化

实验性的 Agent Teams 把持久名册、任务板与邮箱作为协调缝隙（ctx.agentTeams）建立在可续接的子代理之上。多 Agent 协作从提示词约定走向框架原语，是值得跟踪的方向；它目前是实验特性，接口可能变化。

行业：模型厂做 Harness 的逻辑

本文推断，深度求索做 dsh 的商业动机与开源模型战略一致：开源模型降低试用门槛，开源 Harness 把开发者工作流留在自家模型可达范围内，两者互相导流。当 Harness 层出现事实标准，模型层的切换成本会重构——这解释了为何 OpenAI 同期也在经营 plugins 与 skills 目录。

09 / Takeaways

工程师可以借鉴什么

把“注册”设计成可逆效果

审视你自己的 Agent 系统：加载一个工具、一段策略，会不会留下无法撤销的全局副作用？学 Cordis 的纪律——注册时先定义卸载语义，能力变更的可逆性直接决定回滚成本。

借鉴它的三域事件划分

持久事实、进行中拦截、能力策略——三域边界清晰，扩展点选型不再靠感觉。给新功能找位置时先问：它需要存活到重载之后吗？它要打断进行中的工作吗？

把“模型可见即可回放”当不变量

上下文审计、行为回归、事后排障全都受益于这条纪律。做不到全量日志时，至少保证模型可见内容可重建——这是 dsh 值得直接照搬的一条架构原则。

用分层补丁替代源码分叉

定制第三方系统的行为时，用可定位、可审计的补丁层表达差异，而不是维护一个完整分叉。补丁按行 ID 定位、可逐层覆盖的设计，让“你的定制”永远是一份可以单独审查的差异文件。

本文判断如果你在搭建企业内部 Agent 平台，dsh 的架构文档比它的代码更值得精读；如果你只需要一个当下就能用的编码客户端，成熟商业产品仍是更稳的选择。
