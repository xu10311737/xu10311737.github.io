Claude Code 重构 Projects：一个协调器指挥并行 Agent 开 PR，Anthropic 同日亮出内部 3 万并发的底牌

2026 年 9 月 17 日，Anthropic 把 Claude Code 的 Projects（项目空间）从"存文件的文件夹"重构为"对话驱动的协作中心"，beta 先开放给部分 Pro/Max（Anthropic 面向个人的两档付费订阅）订阅者的云端会话。新形态下你只描述目标，一个 Coordinator（协调器）负责评估请求、拆解子任务、派发并行线程、审查产出、组装结果；每条线程是一台跑在云端的完整 Claude Code 会话，持有独立 Git 分支，完成后自动开 PR（Pull Request，向仓库提交代码变更的合并请求）；所有线程共享一份持续积累的工程记忆——技术规格、架构决策、团队偏好——官方称这"降低了对复杂提示词工程的需求"。全程异步，手机可看进度、可插话。

同一天，Anthropic 首次系统披露内部 Agent（能自主调用工具、多步完成任务的 AI 程序）规模化数据：内部研发平台任一时刻约 3 万个 Agent 并发工作；Claude 主导 26% 的核心 AI 研发（达到自动化等级 AL4——AI 从高层指令起端到端主导大部分工作、人做监督，六个月前不足 1%）；每月超 10 亿决策、在线监控拦截其中 0.002%。竞品 Cursor 已在 7 天前发布同构的 Projects（协调器+共享上下文+云执行，内部数据：新用户合并 PR 量 +30%、重度用户 6 倍）——"编排层"正在从单家产品的技巧变成全行业的范式。

先给结论这次发布真正值得注意的不是"又一家做多 Agent"，而是把三件事焊成了一台工程工厂：用协调器解决"人盯不过来"，用 Git 分支/PR 解决"并行互不干扰"，用共享记忆解决"每个新会话都要重新教"。工程师可以直接带走三件事：把分支与 PR 当作 Agent 之间的通信协议、让指挥者永不执行（只委派不动手）、把子 Agent 的学习沉淀成持续同步的共享资产。同时保持清醒：26% 这类数字来自厂商自定义刻度的自我测量，产品处于 beta——无服务等级协议（SLA，Service Level Agreement，厂商对可用性与性能的正式承诺）、成本放大系数未披露——本篇基于官方公开材料分析、未实测该产品。

01 / Decision brief

TL;DR（太长不看）：从"文件夹"到"指挥台"

01 / WHAT

发生了什么

Anthropic 于 09-17 重构 Claude Code 的 Projects 并开启 beta（部分 Pro/Max 云端会话用户）。项目不再是一堆文件，而是一个对话界面：协调器拆解目标 → 并行派发 worker 线程 → 每线程独立云端会话+独立分支+自动 PR → 审查组装。滚动计划：本周内扩大到更多 Claude Code 用户，其后打通聊天、Cowork 与团队/企业版；现有项目文件不受影响，随全端升级迁移。

02 / WHY

解决谁的问题

要用 AI 做"超出单个对话窗口的工程"的团队。单会话 Coding Agent 有三堵墙：上下文窗口（模型一次能装进的工作记忆）塞不下大工程、想并行就要人肉开 N 个终端复制粘贴、每开新会话就丢一次上下文。重构后人类从"操作员"变成"甲方"：定目标、看板式跟进、拍板合并——官方类比是"像给幕僚长（chief of staff）派活"。

03 / HOW

核心机制

三层结构。协调器只拆解派发不写代码——委派使它永不阻塞、随时响应新指令；worker 线程即完整的 Claude Code 云会话（独立分支与仓库副本，可再起子代理、循环、工作流细分任务）；shared memory（共享记忆）让所有线程读写同一份随项目增长的记忆——规格、决策、偏好，甚至"动计费服务前先问谁"。

04 / SHIP

生产判断

规模佐证与风险并存。同日内部测量报告给出 3 万并发、26% AL4、月 10 亿决策、0.002% 拦截率；但产品是 beta：官方明言项目会更快耗尽用量限额（可为协调器与线程分别配模型与投入档位）、无 SLA、并行合并冲突的实际频率未披露；竞品 Cursor 先发 7 天且已全员可用。第三方榜单上 Anthropic 系模型占 Agent 榜前十中的 6 席，底子够硬。

02 / Background

背景与问题：单会话撞墙，全行业在同一个答案上会师

单会话 Coding Agent 有一条天然边界：对话窗口。窗口内它是高效的结对程序员；窗口外——一个要动几十个文件、开几百个 PR 的工程——它就需要人类来当"外置内存"和"调度器"。这不是模型能力问题，是协作结构问题。

A单会话的三堵墙

窗口墙：上下文窗口塞满后早期内容被挤出工作记忆，Agent"忘记"项目约定与早期决策。人肉墙：想并行就要开 N 个终端、人肉复制粘贴上下文、人肉汇总结果——人成了吞吐瓶颈，并行度上限是人的耐心而不是算力。遗忘墙：每开一个新会话，Agent 从零开始——重读代码库、重新约定规范；它在这个会话里学到的一切随会话关闭蒸发。三堵墙指向同一个结论：缺的不是更聪明的模型，而是一个能把大工程切成可并行单元、又能让单元间共享状态的编排结构。

B行业把同一个坑踩成了同一个答案

Cursor 在 2026 年 2 月提出"第三纪元"愿景：Agent 舰队承接整个工作体而非单次任务，并于 09-10 落地 Projects beta、当日开始全员开放。Anthropic 09-17 发布同构的 Projects 重构，并在同一天公开内部规模的量化测量与监控设计（见核心原理章）——编排、测量、安全是同步在建的。模型层的第三方佐证：Arena Agent 榜前十中 Anthropic 系模型占 6 席（数据源 04）。发布次日早间，中文科技媒体即以"大重构"为题大幅报道，讨论焦点集中在"内部 3 万 Agent 并发"与"26% 核心研发由 Claude 主导"两个数字（数据源 05）。（本文推断）7 天内两家头部厂商先后发布"协调器+共享上下文+云执行"的同构产品，说明这不是巧合，是范式收敛。

一个反直觉的细节：人被摆在更显眼的位置。协调器被官方类比成幕僚长——你给它下简令（brief），它回报进展；上线动作（merge PR）仍由人拍板。两家的量化口径也说明同一件事：Cursor 披的是"用户合并 PR 量 +30%、重度用户 6 倍"，Anthropic 披的是"Claude 主导 26% 研发"——量化的都是产出与渗透，而不是"无人化"。多 Agent 编排的目标不是消灭人，而是把人挪到"验收+决策"的位置。

03 / Mechanism

核心原理：目标进对话，PR 出仓库

整个系统的接口是一个对话：你说清楚要什么，系统把"什么"变成一组并行的"怎么做"。官方给的示例是"把应用结账链路的 p75 延迟（第 75 百分位的延迟水位——75% 的请求都快于这个值）降下来"——协调器给每个接口各开一条线程做性能剖析、试验优化、开 PR；跨仓库工程（如让 API、Web、移动端三个仓库联动弃用某个旧接口）则每仓库一条线程，迁移调用方、跑测试、开 PR，还会告诉你先合并哪个。

01 / GOAL你定目标在项目对话里描述要做成的事；配置云端环境、连接器、插件、项目指令与模型。
02 / DECOMPOSE协调器拆解Coordinator 评估请求、拆子任务、派发并行线程；它不写代码只指挥——委派使其永不阻塞。
03 / PARALLEL线程并行干活每线程=云端 Claude Code 会话+自己的 Git 分支与仓库副本；跑测试、提 PR；线程内可再起子代理/循环/工作流。
04 / REVIEW审查与组装协调器检查产出、跟进测试；重叠改动引发合并冲突（merge conflict）时按普通 PR 流程解决。
05 / MERGE人拍板合并PR 走既有 review 流程；进度手机可查、随时插话——全程异步，不需要人守着。
30,000Anthropic 内部研发平台任一时刻的并发 Agent 数（2026-08）。规模本身就是编排结构可行性的证据：没有这层结构，3 万个并发会话只会产出 3 万份需要人盯的日志。
26%核心 AI 研发中由 Claude 主导（AL4，AI 从高层指令起端到端主导大部分工作、人做监督）的占比，六个月前（2026-02）不足 1%；90% 以上研发工作流达到 AL3（AI 协作级）及以上。AL 刻度核心三档见"创新与差异"章。
0.002%每月超 10 亿决策中被在线监控拦截的高风险占比（约 1/47,000）；被拦截动作由人类在一周内复核。

共享记忆：把"重新教"变成"继承"

官方给了三个具体例子：项目记得"发布改到周五了"、记得"为什么砍掉 export 功能"、记得"动计费服务前要先问谁"。每条线程都往共享记忆写、也都从里面读，同步是实时的；除了技术规格与架构决策，它还会记住你的协作偏好（比如汇报要多细），并可调整主动汇报（check-in）的频率。（来源事实）

官方认为这直接"降低了对复杂提示词工程（prompt engineering，通过精心设计输入引导模型行为的技术）的需求"。（本文推断）这本质上是把 Agent 的 onboarding（入职引导）成本从"每个会话一次"摊销成"整个项目一份持续资产"——与 Cursor 的共享上下文（"一个 Agent 学会怎么测试某个服务，所有未来 Agent 都能直接用"）是同一个思想，两家都押注"记忆是编排的地基"。

3 万并发的另一面：监控是规模的前提

测量报告披露了内部平台的管控设计，三层叠加：

  • 在线层：100% 的 Agent 动作在执行前过检、通常秒级返回；被拦截动作由人一周内复核。
  • 离线层：100% 的执行记录（transcript，Agent 执行过程的完整日志）事后全量摄入，每周约 10 万条被标记、由分类器审阅，约 50 条升级人工。
  • 身份层：每个 Agent 持独立身份，数据绑定身份、跨模型升级持久保留、可按 Agent 跨时间审计；Agent 间通过开放式消息系统通信，每条消息绑定身份、附原始引用，Agent 之间可以互相纠正错误。

算力面上，7 月 13-20 那一周约 6% 的 AI 研发算力投向安全与对齐研究，AI 主导的研发中约 12% 的算力投向安全。（来源事实）

规模不在算力在线程里，而在监控在前面。这个三层设计解释了为什么"并行 Agent 工厂"先出现在安全文化最强的厂商内部：没有监控层的并行只是放大风险，有监控层的并行才是产能。反过来也成立——外部用户拿到的是编排产品本身，Anthropic 内部这套监控栈并不随产品直接交付，企业接入要自建对应层（见工程化视角）。

04 / Differentiation

创新与差异：两个"不发明新东西"的决定

这轮重构里真正新的东西很少——两个关键决定都是"不发明"，第三个创新则发生在度量衡上。三个动作分别解决并行、指挥与可信的问题。

A把 Git 分支/PR 当成 Agent 间的通信协议

并行多 Agent 的老问题是"互相踩脚"：两个 Agent 改同一处代码，后写的覆盖先写的。Anthropic 的答案不是发明新的协调协议，而是把软件工程用了十五年的协议直接搬过来：分支天然隔离（每线程在仓库副本上干活）、PR天然可审查（人审的是变更而非过程）、合并冲突天然可见（冲突在合并时暴露而不是运行时炸开）。再叠加跨仓库的"合并顺序建议"，等于让 Agent 团队复用人类团队的全部协作语法。创新不在零件，在"不发明新协议"这个决定本身——（本文推断）这也是它能直接嵌进现有团队工作流的原因：对仓库来说，Agent 开的 PR 和实习生开的 PR 走的是同一条路。

B协调器只委派、不执行

传统多 Agent 框架的规划节点经常"顺手动手"，于是规划者变成瓶颈：它执行时就无法响应新指令。Coordinator 的设计约束是只拆解、只派发、只审查——官方类比幕僚长。这个"不执行"让指挥通道永远畅通：人可以任意时刻插话改方向，代价是所有执行都发生在下游线程。（来源事实）Cursor 的协调器是同一约束——"不写代码、只指挥，因此从不阻塞"。（本文推断）两家在同一个设计点上同构，进一步印证这是行业收敛后的共识解，而非某家的巧思。

等级含义
AL3AI 协作级——在人类的密切指导下，AI 完成大块工作
AL4AI 主导级——从一条高层指令出发，AI 端到端完成大部分工作，人类做监督
AL5完全自主级——AI 独立完成任务，无需人类介入

还有一个讨论最少的创新：把"Agent 采用度"本身做成可测量对象。自动化指数的测法（来源事实）：每周采样 20% 员工，由一个 Claude 研究 Agent 审读 Slack 与内部文档，归类约 15,000 条粒度任务，冻结成 542 节点的任务树，再由判分模型逐条对照 AL 刻度（0-5 级，数字越大 AI 主导度越高，上表为核心三档）定级、按人力时间加权。判分一致性也一并公开：模型与人完全一致率 59%（人与人之间只有 35%），相差一级以内的一致率 97%。当所有厂商都在说"AI 很能干"时，拿出刻度、样本量、一致性上限与第三方评估计划的，这是第一家。

05 / Competition

竞品对比：7 天内先后落地的同构双子

Cursor 与 Anthropic 的 Projects 在架构上高度同构：协调器只委派、云端默认执行、跨 Agent 共享上下文。差异集中在入口、触发方式与数据披露的取向。模型层的第三方佐证：Arena Agent 榜前十中 Anthropic 系模型占 6 席、榜首 Claude Fable 5.1（Max）净提升 13.71%（数据源 04）——编排产品的竞争底下，是模型 Agent 能力的竞争。

对比结论（本文推断）：架构同构度极高，选择题暂时是生态题——主力在 Claude 生态、需要移动端异步指挥的选 Anthropic；需要 Slack/定时/PR 事件驱动的自动行动选 Cursor。两者都在 beta：Anthropic 的移动异步与多仓库编排独有但开放面窄，Cursor 的订阅触发更自动化但生态限于 IDE。两边的数据都是厂商自报（一个报过程渗透、一个报产出倍数），生产采用前用自己的仓库各跑一个试点比任何对比表都可靠。

（本文推断）对照开源路线更能看清这代产品的位置：LangGraph、CrewAI、AutoGen 一类框架早已能搭出"主管拆解、子 Agent 执行"的结构，编排逻辑本身不是护城河。差别在产品化完整度——Projects 把云端执行环境、Git 原生交付、共享记忆、用量分层打包成开箱即用的一体，代价是编排逻辑锁在厂商生态内、不可魔改；开源框架正相反：编排可控、可接私有模型，但执行沙箱、权限、监控、记忆存储全要自建。

选型判据：要快速上量、接受托管边界，用产品；要控制编排与数据边界、且有平台工程团队，用框架自建——Anthropic 内部那台 3 万并发的平台，正是"自建框架路线"能跑通的存在证明。

06 / Production lens

工程化视角：从"能演示"到"能上线"隔着什么

三个问题按落地顺序排列：接入前要准备什么、接入后什么会被改变、Demo 与生产之间还差什么。每一项只谈工程动作，不谈愿景。

Q1生产接入要过哪些关

  • 仓库与 CI 就绪：Agent 线程以独立分支提交 PR，意味着 PR 模板、CI 门禁、测试覆盖率要先行达标——不达标的 CI 会被并行线程放大成 N 倍噪音。
  • 权限与边界：云端会话要访问你的仓库与连接器；涉内网或私有代码的场景，要么等"跑在你自己机器上"的能力（官方称"很快"），要么走团队/企业版方案。
  • 用量预算：官方明言项目会更快耗尽限额，务必用"协调器与线程分别配模型/投入档位"的旋钮做成本分层（规划用强模型、执行用快模型的思路）。
  • 审查流程：Agent PR 涌入后人审是新的瓶颈，先定义哪类 PR 可自动合并（低风险+测试全绿）、哪类必须人审。

Q2对现有研发架构的冲击

Code Review 变成 Code Acceptance：从"人写人审"变为"Agent 写、人验收"，review 队列管理与合并顺序成为新的运维对象——Anthropic 专门做"先合并哪个"的建议正说明这是高频痛点。CI 资源放大：N 条并行线程约等于 N 倍构建与测试负载，容量要预留。权限与审计模型：参考 Anthropic 内部做法——Agent 独立身份、动作执行前全量过检、记录事后全量摄入；外部用户目前需要自建这层（内部平台的安全栈不随产品直接交付）。（本文推断）技能结构迁移：团队时间从"写码"向"指挥+验收"移动，需求拆解能力与审查能力的权重上升。

Q3Demo 与生产之间的三段距离

  • 成熟度距离：beta 阶段部分用户可见、无 SLA；网页与桌面端的旧 Projects 尚未升级（官方称全端统一后迁移），能力面与文档面都还会动。
  • 量化距离：并行线程的 token（模型处理文本的最小单位，约合四分之三个英文单词）成本放大系数、合并冲突的真实频率、错误记忆的清除机制，全部未披露——上生产前必须在自己的仓库上小样本实测这三项。
  • 参照系距离：Cursor 的 +30%/6 倍与 Anthropic 的 26% 都是厂商自报；且 Anthropic 内部 3 万并发的那台平台配了完整监控栈，外部用户拿到的是编排产品本身——监控、身份、审计需要自己补齐，这是最容易被 demo 掩盖的一段。
07 / Risk register

局限与风险：哪些数字要打折扣听

按对决策的影响力排序：数字怎么打折、成本怎么估、哪里会先出事——每条附一个可执行的缓解动作。

自测自报的方法学折扣

风险等级：中高

自动化指数由 Anthropic 自定义、判分的是 Claude（Claude 判 Claude 的任务等级）。模型与人完全一致率 59% 虽高于人与人的 35%（说明刻度可用），但"完全一致"只有六成；26% 是 2026-08 的单月横截面、周采样 20% 员工；AL3 的"大块"与 AL4 的"大部分"边界本身主观。第三方评估者计划目前只是计划。

成本放大系数未知

风险等级：中高

N 条并行线程的 token 开销随 N 放大是物理直觉，但官方只提示"更快耗尽限额"，没有给出"每个 PR 的真实成本"数据；协调器与线程的模型/档位分层虽可缓解，预算模型仍只能自己建。beta 期先设项目级用量上限再放量。

协调器单点

风险等级：中

拆解方向错误时，错误被并行放大 N 倍再交给人审。规划质量的关键变量（协调器用什么模型、计划要不要人审后放行）官方没有给默认策略；高成本任务前先在对话里过一遍计划再放行线程，是 beta 期最便宜的保险。

共享记忆污染

风险等级：中

错误决策一旦写入记忆（"这个服务不用写测试"这类），会被所有后续线程继承；清除机制、版本回滚、记忆的写入权限均无公开说明。这与"越用越聪明"类系统共享同一个未解问题：记忆是资产，也是污染面。

合并冲突的现实频率

风险等级：中

"如同普通 PR"的说法把问题说轻了：Agent 线程不像人类同事会主动避让别人正在改的文件，官方未披露任何线程间的编辑范围协调机制——同文件并行触发的冲突概率可能显著高于人类协作，冲突解决本身也要消耗协调器与人工。

拦截率的双面解读

风险等级：中低

0.002% 既可以读作"监控精准"（月 10 亿决策只拦万分之二、且有人工一周内复核），也可以读作"漏放"——离线层每周约 10 万条标记最终只约 50 条升级人工，漏检样本无法从这个数字本身排除。企业接入时按自己的风险预算决定叠加哪层。

诚实声明：本篇全部结论基于官方博客、测量报告与竞品公开材料，未对该 beta 做一手实测；beta 分批开放，实际功能与本文描述可能存在出入。上生产前，请以自己仓库上的小样本试点数据为准。

08 / Outlook

未来方向：从"会话"到"项目"的产品原子迁移

官方路线很短，推断很长——分开摆，别混着读。左边是发布方白纸黑字的计划，右边是本文的三个判断。

A官方路线（来源事实）

线程目前全部跑在云端，官方称"跑在你自己的机器上"很快到来；一周内扩大 Claude Code 用户覆盖，之后聊天、Cowork 与团队/企业版全端统一升级、现有项目文件随迁。测量报告同时给出制度化承诺：计划嵌入独立第三方评估者，给予与内部风险团队可比的访问权限——把"信不信 26%"变成可以外部核验的问题。

B三个走向（本文推断）

编排层标准化：协调器+共享上下文+云执行在 7 天内被两家头部厂商同构发布，会像多 Agent 框架里"主管节点拆解派活"的 supervisor（主管）模式一样，固化成 harness（给模型接上工具、存储与循环逻辑的工程外壳）的默认结构；下一轮差异化在记忆治理、监控与权限模型，不再在"能不能并行"。产品原子从会话迁到项目：会话是一次性的（上下文随关闭蒸发），项目是持久的（记忆跨会话积累、跨端同步），入口随之从终端扩展到手机——两家的移动端与事件订阅都在把工作重新定义为"始终在线、随时介入"。测量方法被效仿：刻度+样本量+一致性上限的披露方式，把"AI 采用度"从宣传话术变成可审计指标；先效仿的是大厂内部工程效能团队，独立测量机构的出现只是时间问题。

09 / Takeaways

工程师可以借鉴：六件今天就能抄走的事

让每条 Agent 任务以"一条分支一个 PR"交付

不要让多个 Agent 共享工作区：先把手头的 PR 模板与 CI 门禁设成硬标准，再给 Agent 发独立分支的权限；两个执行体的改动冲突一律留到合并阶段解决，绝不在运行时协调——隔离、可审查、可回滚三个属性 Git 已经免费给了，人类团队的整套协作语法直接复用。

把规划节点做成只读

在自己的多 Agent 系统里，规划者对仓库只有读权限、没有写权限，产出只能是任务清单。检验标准很硬：人在任何时刻插入新指令，规划者必须能立即响应——做不到，说明它还在"顺手动手"。这是两家头部厂商独立收敛出的同一设计约束，要抄就抄这个约束本身。

给项目建一份所有子 Agent 读写的学习档案

记录"怎么测、什么规范、动什么先问谁"。最小实现是仓库里一个 markdown 文件：每条线程开工前读、收工后追加。重点是治理——定期人工清一遍错误条目，因为记忆既是资产也是污染面，一条错误记忆会被所有后续线程继承。

监控三层直接抄

执行前全量过检（在线拦截）+ 事后全量摄入并分级筛选（离线标记）+ 身份绑定与引用溯源（可审计）。并行度每放大一个数量级，这三层的必要性就涨一个数量级——先于规模建监控，而不是反过来。

用 AL0-AL5 给自己的团队定刻度

把工作拆成可判定的任务清单，定期测"AI 主导占比"与"AI 协作占比"，比"感觉 AI 越来越能干"可管理得多；顺手记录判分一致率并公开它，数字的可信度会大不一样。

把"等结果"从工作时间剔除

把验收环节设计成手机上随时可介入的：看进度、插一句话、拍板合并。异步指挥不是体验优化，是吞吐优化——人不再被"盯着跑"绑定在工位上，等待时间才真的归零。
