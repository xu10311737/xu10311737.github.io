FINAL-Bench 开源 ZTC 零 token 置信度探针：模型的自报置信度测出来是抛硬币——别问，直接读隐藏层，0.06 秒、零个 token、45 KB

2026 年 9 月 20 日，VIDRAFT 团队以 FINAL-Bench 名义在 Hugging Face 博客发布 Zero-Token Confidence（ZTC，零 token 置信度）：不问、不生成，直接从模型的隐藏状态向量（hidden state：模型逐层处理完输入后，网络最后一层在每个 token 位置留下的数字向量——模型"读完卷子后脑子里剩下的那团印象"，不经过输出层、不变成文字）读出"这个答案是对的"的校准概率（calibration：把原始分数映射成贴近真实发生频率的 0-1 概率）。在 2,018 项共享基准上，模型自报置信度这一信号的判别力只有 AUC（Area Under the ROC Curve，ROC 曲线下面积：衡量信号区分"答案对/错"的能力，0.5 等于随机猜，1.0 为完美）0.5000——精确等于抛硬币；在另一组 539 项保留集实验里，同一个模型被"问出来"是 0.7646、"读出来"是 0.8801。两组数字来自不同题集与评测模式，方向一致：问不如读。配套发布三件东西：自带探针的 397B MoE 模型 Darwin-397B-ZTC（GPQA Diamond 93.43 分（百分制）；MoE 即 Mixture of Experts 混合专家架构，GPQA Diamond 为研究生级专家科学问答基准）、给其他模型答案当判官的 ZTC-Judge-27B（覆盖五个领域）、以及可在线对战的门控演示 Gate Arcade。

真正值得精读的是这份发布里三组"拆台"数据。一、表面基线：只看答案长度与格式、完全不读内容的对照方法拿到 0.7036，而两个已发表的验证器——open-jev 4B（JEV 生态的开源 4B 验证器）与 Lynx 8B（Patronus AI 开源的幻觉检测模型）——双双低于它——等于被量化曝光"没在干活"。二、统计纪律：探针的真实拟合位于打乱标签的零假设分布之上 9~13 个标准差（置换检验），留一域交叉验证（leave-one-domain-out：探针从未见过测试领域，超参数只在训练领域内选取）仍有 0.7572。三、架构反直觉：180B 级模型在探针质量上垫底，预测因子是隐藏层宽度与全注意力占比，不是参数量。门控一次 0.0615 秒、比它守卫的生成工作便宜 26 倍，探针本体是一个 45 KB 的 .npz 文件（NumPy 数组存档格式）、四行代码接入。本文的能力描述均来自官方博客、模型页与公开资料，未包含作者实测数据。

先给结论值得精读的三个理由：一、它把"置信度信号"的成本结构从"再跑一次模型"改成"读一次向量"——当验证比被验证的工作便宜 26 倍，Agent（智能体：能自主规划并执行多步动作的 AI 程序）才能从"抽样验证"升级为"每个动作都过闸"；二、0.5000 这个数字对所有拿"问模型自己"的置信度做路由（routing：按信号决定走哪条路径，如执行/重试/升级人工）的产品是一记直接警告——路由可能建立在噪声上；三、它示范了"论文到生产"的最短路径：四年前的学术结论被压缩成 45 KB、四行代码的即插即用部署物。一句话评价：方向可信、工程干净——数字全部来自单一自建基准、只适用于自托管开源模型；当"便宜的门控初筛"引入可以，当"最终裁决"用不行。

01 / Decision brief

TL;DR（太长不看）：把"问模型"换成"读模型"，置信度从免费的噪声变成免费的信号

01 / WHAT

发生了什么

FINAL-Bench（VIDRAFT）发布零 token 置信度技术 ZTC：用一个线性探针（linear probe：只做一次加权求和加一次概率映射的极小分类器）读模型最后一个 token 的隐藏状态向量，输出"答案正确"的校准概率。零生成 token、单次 0.0615 秒（27B 模型、4×B200 官方实测）、探针 45 KB、四行代码接入。

02 / WHY

解决谁的问题

Agent 的每个动作（删数据、发起支付、跑部署脚本）都缺一道"要不要执行"的闸门。现有信号两头不讨好：问模型自己——2,018 项多域基准上测出 AUC 0.5000 的噪声；跑生成式验证器——一次完整推理的开销，与被验证的 Agent 抢同一份预算。ZTC 把成本与质量两个死结同时解开。

03 / HOW

怎么做到的

在模型最后一层的隐藏向量上训练线性探针并预置校准常数；两种工作模式——self-readout（模型读自己刚生成的答案，AUC 0.8801）与 judge（ZTC-Judge-27B 读任意模型的答案，跨五域）。训练数据不随部署走，落地产物只有权重向量、标准化项、校准常数三样东西，装进一个 .npz 文件。

04 / SHIP

生产判断

只对自托管开源模型可用（闭源 API 不返回内部状态；vLLM 已有隐藏状态提取通路）；探针与模型版本强绑定，模型更新需重训重验；全部核心数字来自单一自建基准，自己的分布上要先重测 AUC 与阈值再上线。

02 / Background

背景与问题：Agent 的动作闸门，缺一个又便宜又诚实的信号

Agent 工程里最贵的错误不是答错一道题，而是把错误答案变成一次真实执行——删掉不该删的行、发起不该发起的支付。所以 harness 的标准设计是给每个"即将执行的动作"配一道闸门：置信度够就放行，不够就 hold（按住不执行）。闸门需要信号，而今天拿信号的三种方式，全都是"问"出来的。

A三种"问出来"的信号与它们的账单

  • 自报置信度：在提示词里加一句"给出你的把握（0-100）"。免费，但 ZTC 的测量显示它在 2,018 项多域基准上是 0.5000 的噪声——模型把自信的语气当成了自信本身。另一篇 2026 年 9 月 17 日提交的论文（arXiv:2609.20541，Meyer 等）补上了它的脆弱性：对同一批固定答案换等价措辞重新询问，自报分数平均波动 0.043~0.084，在 0.8 阈值处翻转 4%~9% 的决策。
  • 自洽采样（self-consistency）：同一问题再生成几个答案看一致程度。每个样本都是一次完整生成的成本；而且一致性会放大共识错误——上述论文测到两个模型分别有 4/9 与 2/8 的错误答案获得全部样本的一致支持。
  • 生成式验证器：让另一个模型读答案下判定，如 Jev（本系列 2026-09-17 期介绍过的结构化判断模型，其生态常写作 JEV）。质量可用但贵：一次完整推理，与被验证的 Agent 抢同一份 token 预算。这个生态正在快速膨胀：OpenRouter 新模型榜上 Jev 1.13 在列（数据截至 2026-09-20）、Hugging Face 2026-09-20 盘点 JEV 生态已有 13 个验证器、LangChain 同日发布 Jev-as-a-Judge 评测教程。

BFINAL-Bench 的赌注：信号本来就在里面

2022 年 Kadavath 等人的论文《Language Models (Mostly) Know What They Know》已经证明：模型的内部状态携带"自己答案对错"的信息，可以直接用探针读出。四年里这条学术线基本停在论文与 notebook 里。FINAL-Bench 的赌注是把它压成生产件：不需要随行训练数据、不需要额外服务、不占第二张卡——45 KB、四行代码。于是同一个模型上，"问"与"读"给出了两组平行世界的数字：Darwin-397B 问 0.7646、读 0.8801；Qwen3.5-27B 问 0.6141、读 0.8388。

核心问题的重新表述。"置信度信号"的成本与质量一直被当成二选一：便宜的自报不可靠，可靠的生成式不便宜。ZTC 把这道单选题拆成两道题：信号从哪来（生成的文本 vs 内部的向量）决定质量上限，信号怎么取（采样生成 vs 读出向量）决定成本下限。读出式把两个维度同时解开——这就是榜单上"0 token"那一列的真正含义。

03 / How it works

工作原理：一次前向传播，读模型"读完卷子那一刻"的内部状态

ZTC 的完整链路只有六步，全部发生在推理过程内部，不产生任何输出 token：

STEP 1组装输入问题 + 候选答案拼成 prompt 喂给模型；judge 模式下读的是其他模型的答案
STEP 2前向传播模型逐层处理输入，不做采样、不生成任何文字——"零 token"的来源
STEP 3取出向量抓取最后一层在最后一个 token 位置的隐藏状态向量（几千维）
STEP 4标准化减均值、除标准差（.npz 里的 mu/sd 两项），消除各维度的量纲差异
STEP 5探针打分向量与权重向量 w 做点积，得到原始分数 s——只是一次加权求和
STEP 6校准输出用标定常数把 s 映射成 0-1 概率 p，超过阈值放行，否则 hold
0.8801读出式 AUC（self-readout，539 项保留集）；同一模型"问出来"只有 0.7646
0.0615 s单次门控耗时（27B、4×B200）；对比生成一个候选答案的 1.631 秒
45 KB探针部署物：权重向量 + 标准化项 + 校准常数；无训练数据、无依赖、无服务调用
26×门控比它所守卫的生成工作便宜的倍数——"验证像舍入误差一样便宜"

探针本体：四行代码 + 一个 45 KB 文件

部署物是一个 .npz 文件，里面只有三样东西：权重向量、标准化项、校准常数。官方给出的完整接入代码：

z = np.load("ztc/ztc_probe_darwin397b.npz")
h = model.model(**inputs).last_hidden_state[0, -1].float().cpu().numpy()
s = ((h - z["mu"]) / z["sd"]) @ z["w"]
p = 1 / (1 + np.exp(-(z["cal_A"] * (s - z["s_mean"]) / z["s_std"] + z["cal_B"])))

两个值得注意的工程细节：第一，读的是 last_hidden_state[0, -1]——第一条序列、最后一个 token 位置的向量，也就是模型"写完答案那一刻"的内部状态；第二，校准不是裸的 sigmoid（把任意分数压成 0-1 的 S 形函数），而是带两个标定常数的仿射变换——这保证输出的 0.8 尽量对应"真实正确率约 80%"，是一个可解释的概率，而不只是一个能排序的分数。

两种工作模式

  • self-readout（自读）：模型读自己刚生成的答案。这是数字最亮的模式——Darwin-397B 问 0.7646、读 0.8801（+0.116）；Qwen3.5-27B 问 0.6141、读 0.8388（+0.225）。适合"模型对自己输出把关"的场景。
  • judge（判官）：FINAL-Bench/ZTC-Judge-27B 读其他任意模型的答案，覆盖五个领域。榜单第一名的 0.7394 就是 judge 模式（397B 探针）。适合"给闭源或第三方模型的答案验货"的场景——前提是答案文本能拿到。
04 / Innovation

创新点：信号不新，把信号压成 45 KB 部署物的做法新

先厘清边界："模型内部状态携带对错信息"是 2022 年就发表的学术结论，ZTC 没有发明这个信号。它的创新在三件别的事上：

  • 工程化压缩：从研究方法到生产件。Kadavath 等人的探针活在论文与 notebook 里，复现者要自己处理模型加载、层选择、探针训练、校准一整套。ZTC 把产物压到"一个 45 KB 文件 + 四行代码"：训练数据不随行、无额外依赖、无服务调用。一条学术结论要进生产，先要回答"部署物多小、依赖多少、要不要起服务"——这份发布给出了目前见到的最短答案。
  • 对照榜单的方法论：表面基线是最狠的一笔。2,018 项、同一 harness、所有验证器跑同一批题。其中"表面基线"——只看答案长度与格式、完全不读内容的对照组——拿到 0.7036，把两个已发表验证器（open-jev 4B 0.6844、Lynx 8B 0.5157）压在身下。这一笔对所有做验证器评测的人该成为标配：没有表面基线的验证器评测，证明不了验证器在读内容。
  • 统计纪律与架构发现。置换检验（permutation test：把标签打乱重做拟合、看真实结果落在随机分布的什么位置）：探针在 200 次打乱标签的重拟合之上，真实拟合高出 9~13 个标准差——排除了"碰巧拟合"的解释；留一域交叉验证 0.7572，说明信号跨领域可用而不仅在训练分布内有效。再配上"探针质量由隐藏层宽度与全注意力占比预测、与参数量无关"的架构结论（详见下章）——一份社区发布里少见的统计纪律。

成本经济学的换算。官方两组实测：27B 模型上，生成一个候选答案 1.631 秒，ZTC 门控 0.0615 秒——便宜 26 倍；Darwin-397B 用 8×B200 在 270 秒内评完 2,018 项（含前向传播，0.13 秒/项）。原文的推论值得整段记住：生成 token 的验证器与你的 Agent 抢同一份预算，读出式的便宜像舍入误差——于是你可以给每个动作都装闸门，而不是只给抽样出来的少数动作装。

Gate Arcade：把三套闸门放进同一台街机

三条赛道接收完全相同的动作流（删三行数据、发起一笔支付、跑部署脚本）与相同的 300 秒预算，记分规则：正确动作 +1、错误动作 -1、hold 记 0。一条不设闸门、必须全部执行；一条用文本阅读式验证器；一条用 ZTC。400 场下来：无门 -3.9、文本验证器 +13.0、ZTC +29.1——98% 的场次获胜。门控把执行准确率从 49% 抬到 65%；同一 300 秒里 ZTC 处理了文本验证器 2.2 倍的动作量，因为它的闸门近乎免费。演示还留了个巧思：无门赛道上玩家唯一的提示就是模型的自报置信度——试过的人会直观记住那个数字值多少。

一个容易被误读的边界。"自报置信度 = 0.5000"是这套 2,018 项多域基准上的测量结果，不是普适定律。2026 年 9 月 17 日提交的另一篇论文（arXiv:2609.20541，Meyer 等）在 100 道 TriviaQA（经典琐事问答数据集）上测得：在核查并修正基准答案标注本身的错误之后，口头自报置信度的 AUC（论文写作 AUROC，与 AUC 同一指标）可达 0.956/0.937，分别为两个模型家族的结果——但换等价措辞就波动 0.043~0.084、在 0.8 阈值处翻转 4%~9% 的决策，且自洽采样会一致地支持共享错误。两份证据合起来的图景（本文综合判断）：自报信号在简单事实问答上勉强可用但脆弱，在多域难题上塌成噪声；读出式在测过的场景里稳定得多——但"自报永远没用"与"自报基本可用"都是以偏概全。

06 / Production view

工程化视角：三道关——状态访问权、版本绑定、阈值运营

这套东西要进生产环境，绕不开三个问题。以下分析结合 ZTC 的部署形态与 vLLM 的基础设施现状展开。

一、接入生产需要考虑哪些环节？

  • hidden state 访问权是硬前提：闭源 API 不返回内部状态——ZTC 结构性地只适用于自托管开源模型。通路已经存在：vLLM（主流开源推理引擎）2026-03-30 的官方博客给出隐藏状态提取方案；v0.29.0（2026-09-09 发布）把 extract_hidden_states 纳入 Model Runner V2（PR #49811）。自托管团队从今天起具备全部原料。
  • 探针与模型版本强绑定（本文推断）：45 KB 的权重向量是针对特定模型特定 checkpoint 拟合的。模型微调、量化方案变更、推理后端升级都可能改变隐藏状态的语义——需要建立"模型版本 ↔ 探针版本"的配对管理，模型更新后在保留集上回归验证 AUC，并把配对关系写进部署清单。
  • 阈值标定与漂移监控：榜单 AUC 不等于你的分布上的 AUC。上线前用自己的（问题、答案、对错）数据重标阈值；上线后对"门控命中率"（hold 比例）设移动均值告警——命中率的漂移往往先于 AUC 崩塌暴露分布变化。
  • hold 之后的兜底链路：门控只回答"要不要执行"。hold 之后做什么——重试、换更强模型、检索增强、升级人工——必须预先设计。没有兜底链路的门控只是把错误换成停顿。

二、对现有 LLM 应用架构有什么影响？

三处。第一，置信度路由的信号源换代：cascade 级联选模型、RAG（Retrieval-Augmented Generation，检索增强生成）触发、答案放行——凡靠"问模型自己"拿置信度的环节，都可换成"读状态"，成本从一次额外生成降到一次前向传播的向量读取。第二，验证器分两层：读出式探针（近零成本）部署在每个动作上做初筛，生成式验证器（Jev 类）留给高价值决策做复核——Gate Arcade 里 2.2× 的吞吐差距就是这种分层的预演。第三，自托管的价值权重上升：需要动作级门控的 Agent 工作负载会向自托管推理迁移，闭源 API 在这个能力维度上是结构性缺席的（本文推断）。

三、从 Demo 到生产可用，主要差距在哪里？

四处。①泛化面：所有核心数字来自单一自建基准（2,018 项、一个 harness），judge 模式仅声明五个域，生产分布上的 AUC 未知；②域外衰减已可见：留一域 0.7572 对域内 0.8801，约 0.12 的衰减量就是"分布漂移税"的量级参考，上线前应按自己的域做留一验证；③对抗鲁棒性未验证：探针是一个线性函数，若攻击者能构造影响输入文本的对抗样本，存在把分数推向"高置信"的理论路径——安全敏感场景需要先做对抗测试（本文推断，原文未涉及）；④团队与模型透明度：FINAL-Bench/VIDRAFT 是新团队，Darwin-397B 公开资料有限，成果未经同行评议——把探针当"实验性组件"而非"标准件"引入，配好回归验证再放量。

07 / Risk & Limits

局限与风险：单一基准上的漂亮数字，离普适结论还差三步

单一基准外推 高

2,018 项、一个自建 harness、一支新团队，全部数字未在任何外部基准复现。AUC 与 Gate Arcade 的 98% 胜率都只代表这套基准的分布，换成你的业务题目先重测。

"自报失效"有任务边界 高

arXiv:2609.20541 在简单问答上测出自报 AUC 0.956/0.937（两个模型家族）。0.5000 是多域难题上的结果——把"自报置信度没用"当普适结论引用，会在简单场景误伤一个可用信号（本文综合判断）。

性能领先幅度有限 中

榜首 0.7394 对 JEV 0.7335 只差 0.0059，对表面基线 0.7036 只差 0.0358。judge 模式下 ZTC 赢在成本结构；真正大幅拉开的是 self-readout 的 0.8801——引用数字时分清模式。

探针绑定模型版本 中

模型更新即语义漂移风险；多模型 fleet 需要维护探针矩阵。探针本身便宜，探针的版本管理不便宜（本文推断）。

门控的错误代价不对称 中

阈值偏松，错误动作被放行（演示里 -1 的代价在生产中可能是真实世界损失）；偏紧，频繁 hold 拖慢 Agent。98% 胜率是温和计分规则下的演示数字，生产阈值选择是风险偏好问题而非技术问题。

部署门槛 中

让 397B MoE 读自己并不轻；现实路径是 27B 判官（0.7255）或对在用模型自训探针——后者需要自己攒（问题、答案、对错）标注集，量级参考 ZTC 使用的 2,018 项基准。

08 / What's next

未来方向：置信度成为推理引擎的一等返回字段

  • 推理引擎内置（本文推断）：vLLM 已有 extract_hidden_states 基础设施，自然终点是 confidence 作为 API 的一等返回字段——模型响应自带校准置信度，门控从"外挂探针"变成"引擎原生能力"。先落地的引擎会给自托管栈加上一个闭源 API 给不了的卖点。
  • 验证器预算分层化（本文推断）：全量探针初筛 + 选择性生成式复核的两层预算架构，会取代"单一验证器包打天下"。Gate Arcade 的 2.2× 吞吐差已预演第一层的价值；第二层（何时值得花一次生成式验证）是新的调度问题。
  • 学术侧的统一问题：自报信号的任务依赖性（arXiv:2609.20541）与读出信号的稳定性（ZTC）需要在同一框架下解释——"问与读的差距"（+0.116/+0.225）本身就是一个值得研究的现象：生成时丢失了什么，读出时读到了什么。
  • 结构化判断与读出的融合（本文推断）：Jev 类验证器的 schema 化产出（结构化字段）与 ZTC 的零成本读出并不互斥——探针当第一道便宜闸门，过闸的少数高价值决策再交给结构化判官，两层共享同一套阈值与监控。
  • 模型选型指标的扩容："探针友好度"（隐藏层宽度、全注意力占比）会成为 Agent 门控场景的选型维度——180B 级模型垫底说明，通用跑分与参数量在这个维度上没有话语权。
09 / Takeaways

工程师可以借鉴：五条可以直接搬走的做法

先审计你正在用的置信度信号

产品里凡有"问模型自己把握多大"的路由，先测一次 AUC——对照 0.5 随机线与"答案长度/格式"表面基线 0.7036。两行 pandas 就能算；很多团队会当场发现自己路由在噪声上。

给验证器评测配表面基线

任何自研或引入的验证器，评测时必须包含"只看长度与格式"的对照组——open-jev 4B 与 Lynx 8B 低于基线的教训：不读内容也能拿 0.70，你的验证器高过它多少才是真本事。

把学术信号压成部署物再谈落地

线性探针 + 标准化项 + 校准常数 = 45 KB npz + 四行代码。一条学术结论要进生产，先回答"部署物多小、依赖多少、要不要起服务"——ZTC 给出了可复用的压缩模板。

需要内部状态的能力只能配自托管

extract_hidden_states 是 vLLM 的现成通路。评估闭源与自托管时，把"暴露哪些内部信号"记入决策清单——闭源 API 的能力边界由"愿意暴露什么"决定，而不是由"会什么"决定。

便宜的信号会改变架构形态

验证成本降到被验证工作的 1/26 时，抽样验证变全量门控。评估任何信号源时多算一步：如果它便宜 26 倍，你的架构会怎么改——这个思考顺序比"先定架构再找信号"更贴近真实演化路径。
