DeepSeek-V4.1-Flash：把每个 token 的全局 KV 缓存压到 890 字节——552B 参数的 MoE 为 Agent 负载重新设计整条注意力栈

2026 年 9 月 17 日，DeepSeek-AI 发布论文《DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression》（arXiv:2609.19969）并开源模型权重，论文随即登上 Hugging Face（HF，全球最大的开源模型社区）趋势论文榜第一（数据截至 2026-09-20 积 88 赞）。模型是一个多模态 MoE（Mixture of Experts，混合专家架构：模型由大量"专家"子网络组成，每个 token 只激活其中一小部分）：主干 552B（billion，十亿）参数，另有 196B 的 Engram 记忆模块参数；支持 100 万 token（token：模型处理文本的最小单位，英文约 0.75 个单词）上下文；预训练消耗 45T（trillion，万亿）token 多模态语料。它给长程智能体（long-horizon agent，需要连续工作数十分钟到数小时、跨越大量工具调用与中间结果的 AI 程序）时代的一个部署顽疾开药方：KV 缓存（Key-Value cache，注意力机制为每个 token 在每层保存、推理时反复读取的"记忆条目"）——在 HBM（High Bandwidth Memory，显卡上的高带宽显存，容量最小、单价最高的存储层）中，它把全局 KV 压到每 token 890 字节，约为上一代 V4-Flash 的 1/4；在 SSD（固态硬盘）/主机内存的持久层，配合"有界回放"技术，压到上一代的约 1/8。

真实用量很快证明这不是纸面优化：模型上线即冲上 OpenRouter（聚合数十家模型厂商 API 的路由平台）的用量榜前列（数据截至 2026-09-18），并把"输入重"的 agent 任务基准打进第一梯队——用量与基准明细见下文数据表。更值得注意的是，论文把"愿意花多少算力换多准"做成了模型原生参数：推理力度（reasoning effort）1–100 标量，2026 年 9 月已在其生产 API 以 low/high/max 三档（50/75/100）上线。本文的能力描述全部来自论文与官方公开资料，未包含作者实测数据。

先给结论值得精读的三个理由：一、这是"把成本问题在模型内部解决"的完整样本——KV 压缩不打引擎补丁，而是架构（CED 编码器-解码器分工）、算法（CSA2 压缩稀疏注意力的跨层复用）、精度（FP4 量化）、部署（SWA 滑动窗口注意力分支的有界回放）四层联合设计，训练阶段就为部署近似做好准备；二、prefill（预填充，处理输入的计算阶段）每 token 只激活 8B、decode（解码，逐 token 生成阶段）激活 16B 的非对称设计，直接承认 agent 时代的成本大头在输入侧；三、论文自己划出的边界同样值得读：近似重建"在未测试的边界情况仍可能导致能力退化"，最难任务与闭源前沿仍有硬差距。

01 / Decision brief

TL;DR（太长不看）：四层各砍一刀，Flash 档的容量账这么算

01 / WHAT

发生了什么

DeepSeek-AI 于 2026-09-17 发布并开源 DeepSeek-V4.1-Flash：552B 主干 + 196B Engram 记忆模块的多模态 MoE，100 万 token 上下文，45T token 预训练。prefill 每 token 激活 8B、decode 激活 16B；权重以官方 checkpoint 形式开放在 Hugging Face。

02 / WHY

解决谁的问题

长程 agent 的负载是"输入重"的：长指令、几十轮工具返回、反复回读早期上下文，KV 缓存随上下文线性膨胀，挤占 HBM 容量、SSD 带宽与传输带宽，prefill 计算昂贵——论文引言把三者并列为"进一步降低部署成本的第一瓶颈"。

03 / HOW

怎么做到的

四个正交维度各砍一刀：①CED——decoder 层的全局 KV 从 encoder 中间层投影获得，prefill 计算量约减半；②CSA2（Compressed Sparse Attention 2，压缩稀疏注意力）——层组内共享 KV + Top-K 稀疏注意力（每层只精读 512 个最相关位置）+ 层级索引器；③FP4——主 KV 用 4 bit 浮点存储，后训练插入量化感知训练保精度；④SWA Bounded Replay——短窗状态不入持久层，会话恢复时重算最近 128 个 token。

04 / SHIP

生产判断

890 字节/token 与持久层 1/8 直接改写容量与并发账；推理力度三档 API 是"成本旋钮进接口"的信号；自部署要先算清 Engram 的 203GB 磁盘与逐 token 专家读取带宽（colibri 口径 4.5GB/token）；新注意力栈依赖专用 kernel，引擎适配有周期，第一天别拿官方吞吐当服务等级承诺。

02 / Background

背景与问题：Agent 把推理服务的账单，从"算力"搬到了"存储与带宽"

先看用量结构（OpenRouter，数据截至 2026-09-18）：应用消费榜前十全部是 agent 与 coding 工具——Hermes Agent（Nous Research 的开源自进化 agent）日消费 1.68 万亿 token 居首，Claude Code 以 8,800 亿 token 第二，Kilo Code、Cline、pi、omp、Codex、OpenClaw 分列其后，DeepSeek 自家的 DeepSeek Harness（harness：包裹模型、使其能力可被使用的执行环境，调度循环、工具接口、上下文管理都在这一层）以 1,720 亿 token 首次上榜（第 9）。模型侧，DeepSeek 的请求份额已占 OpenRouter 周榜第二（22.6%，仅次于 openai 的 23.6%），V4.1 Flash 上线即冲到日榜第一（2.62 万亿 token，+16%）、周榜第二（12.9 万亿，+484%）。agent 消费 token 的方式与人对话根本不同：一条长指令、几十轮工具返回、不断回读早期上下文——输入远多于输出，且会话要跨小时驻留。这就是论文所说的 input-heavy（输入重）负载。

AKV 缓存为什么贵：三笔账

①容量账：标准注意力机制为上下文中每个 token 在每一层都保存一份 K/V 条目，随上下文线性增长——百万 token 会话动辄数 GB 显存，直接限制单卡并发数；②带宽账：会话恢复、缓存换入换出要在 HBM、主机内存（DRAM）、SSD 之间来回搬运，SSD 带宽远低于显存，驻留会话一多，"搬缓存"本身就能把服务拖住；③算力账：prefill 要对全部输入做一遍前向计算，输入越长越贵，而 agent 的输入恰恰最长。论文引言的表述是：即便长上下文计算成本已被先前工作大幅降低，prefill 依然昂贵、KV 缓存依然挤压 HBM 与 SSD 容量和数据传输带宽——三者合计构成降低部署成本的第一瓶颈。

B为什么"引擎层优化"不够了

过去两年，主流推理引擎把 KV 优化做成了外挂能力：前缀缓存复用、prefill/decode 分离部署、KV 量化开关、Mooncake 类缓存连接器等；vLLM v0.29.0 就带了一批 DeepSeek V4 专项优化（共享专家融合进 MegaMoE（vLLM 的混合专家计算内核）、MXFP4（OCP 标准的微缩 FP4 格式）索引器 KV 压缩、SM90/SM100 稀疏 MLA（Multi-head Latent Attention，多头潜在注意力）内核等）。但外挂的天花板是模型架构本身：只要模型仍按"每 token 每层各存一份"设计，引擎只能省搬运，省不掉存储与计算的发生。V4.1-Flash 的选择是反过来——让模型结构本身少产生（层间共享）、少存储（跨层复用）、低精度存（FP4）、可丢弃可重建（有界回放），把压缩做进权重。

Flash 档的军备竞赛同期开打。OpenRouter 周榜上，腾讯 Hy4 preview（12 万亿 token）居第三、GLM 5.3 Flash（11.6 万亿）第四；vLLM v0.29.0 同批接入了 Hy4-preview（770B 参数、49B 激活，带 Gated DeepSeek Sparse Attention 与原生 MTP（Multi-Token Prediction，一次预测多个 token 的辅助头，常用于加速生成））和 Qwen3.8-Flash-Next（BF16/FP8/NVFP4 多精度 + MTP）。（本文推断）"Flash 档 = 为 agent 负载特化的高性价比档"正在成为各家共识；DeepSeek 这一仗的差异化打法，是用架构与训练手段而非单纯量化去省。

03 / How it works

压缩原理：四个正交维度各砍一刀，"每 token 每层存一份"被彻底改写

先建立直觉。Transformer（基于注意力机制的神经网络架构，当前大模型的主流结构）生成每个 token 时，注意力层要回看上下文里的全部历史 token；如果每看一遍都重算历史表示，代价不可接受，所以标准做法是把每个 token 在每层算出的 Key/Value"笔记"存下来复用——这就是 KV 缓存。它换来生成快，代价是随"上下文长度 × 层数"线性膨胀的存储。V4.1-Flash 的压缩，是沿四个互不重叠的维度各砍一刀：

CUT 1 / CED算得更少：编码器-解码器分工40 层中只有前 20 层（encoder）真正计算全局 KV；后 20 层（decoder）的全局 KV 由 encoder 中间层经一层小投影直接生成。prefill 计算复杂度从 O(NL) 降到约 O(NL/2)（N 为序列长度、L 为层数），处理输入的激活参数从 16B 降到 8B。
CUT 2 / CSA2存得更省：跨层复用 + 稀疏精读encoder 的 18 个 CSA2 层分 3 组（每组 6 层）：首层 Full 计算主 KV，其余 5 层 Reuse 复用；decoder 的 20 层分 5 组（每组 4 层）：第 1 组首层 Full、其余 3 层 Reuse，第 2–5 组首层 Reindex（复用最近 Full 层的主 KV、仅用自家查询重选 Top-K）、其余 3 层 Reuse。每层注意力只精读 512 个最相关位置，候选由层级索引器从最多 16,384 个位置中筛出。
CUT 3 / FP4数字更小：主 KV 存 4 bit主 KV 用 E2M1 格式（4 bit 浮点：1 符号 + 2 指数 + 1 尾数位）存储，每 16 个通道共享一个 8 bit（E4M3）缩放数；参考 NVFP4 但省掉二级全局缩放，动态范围 448×6=2688 足以覆盖 KV 幅值。旋转位置编码（RoPE）之后量化；短窗口 SWA KV 保持 8 bit。后训练阶段插入量化感知训练（QAT：让模型在训练中就适应量化误差）保精度。
CUT 4 / BOUNDED REPLAY不存可重建：短窗状态不入库滑动窗口注意力（SWA：只回看最近固定窗口的注意力分支，窗口 128 token）的 KV 从不写入持久缓存；会话恢复时只重算最近 128 个 token 的窗口状态。持久层因此只需保存全局 KV——叠加 CUT 2 的 1/4，持久缓存降到上一代约 1/8。
TRAIN-AWARE训练时就知道会被这样部署有界回放等部署近似在后训练中被同步模拟，权重是在"知道"自己将按此部署的前提下训练的——近似损失在训练里被消化，这是与纯部署侧优化最大的不同。

维度机制一句话解释换来的东西
CED（算力层）decoder 全局 KV 投影自 encoder 第 20 层的中间状态（层内小型投影矩阵）"前半场做笔记，后半场只引用"prefill 激活 16B→8B，计算量约减半
CSA2（存储层）层组内 Full/Reindex/Reuse 三模式共享主 KV；Top-K 512 稀疏注意力；层级稀疏索引器（第一级索引建 16,384 候选池）"相邻同事共享一份纪要，只精读被点名的问题"全局 KV 压缩 1/4 的主要来源

SWA Bounded Replay（持久层）窗口状态从不持久化；恢复时 encoder 重算、decoder 前向均限定在最近 128 token；训练中同步模拟"存档只存结论，最近五分钟的细节要用时现场重听录音"持久缓存再砍一半，合计约 1/8

把四个数字连起来读：全局 KV 从"每 token 每层一份"变成"每 token 每层组一份、只存 4 bit、只精读 512 个位置"；持久层再丢掉整个短窗分支。论文图 2 给出的推论同样关键：上下文从 4K 拉到 1M（256 倍），decode 每步计算量按精度权重折算只增加约 1/4——长上下文的边际成本大头被架构吃掉了。

配套模块：同样为"省"而设计的三个组件

  • Engram（196B 条件记忆）：装在第 1、14 层的记忆模块，用 N-gram（连续 N 个词的序列统计，N 取 2/3/4）加 8 个哈希头索引查找表（每头约 1,600 万条目，表尺寸取互异质数，FP8 存储）。推理时寻址是确定性的，嵌入可从主机内存经 RDMA（Remote Direct Memory Access，绕过操作系统内核的内存/网络搬运技术）后台预取——第一个模块的预取与首个 Transformer 块的计算重叠。设计意图：查表比注意力便宜，把一部分"记住"从注意力栈挪出去。
  • DSpark（投机解码）：speculative decoding（投机解码：小模型先草拟多个候选 token、大模型一次批量验证的加速技术）的 DeepSeek 实现——3 个 Transformer 块的小草稿模型，单次前向同时给出 5 个草稿位置的 logits（模型输出层的未归一化对数概率）；Markov 头建模 token 间依赖，置信头预测接受率，调度器按吞吐曲线动态选验证长度。草稿模型在预训练后单独训练（主干冻结），后训练期间继续训练但梯度不回传主干。
  • Single-Pass mHC：把 mHC（混合超连接，一种并行化残差混合结构）的输入混合系数移位一个块，从两遍扫描变单遍；部署内核把残差更新、输入混合、系数预测融合成一个算子，激活内存流量减半。
04 / What's new

创新点：单点技术都有先行者，"训练-架构-部署一条龙"才是差异

诚实的评估是：四刀里的每一刀单拎出来都有学术或工业界的先行者——跨层共享有 IndexCache、YOCO、CLA 等工作，稀疏注意力在 V4 一代已经使用，FP4/NVFP4 是 NVIDIA 主推的格式，投机解码是成熟技术。论文的真正贡献在于把"条目大小（FP4）、序列维度（Top-K 稀疏）、层维度（跨层复用）"三个正交成本维度一次做满，并让每个近似都有训练侧的补偿机制。

A架构内生，而非引擎外挂

对比引擎侧的优化路径可以看清差异：vLLM 对 V4 的适配（共享专家融合、索引器 KV 压缩、稀疏 MLA 内核）是一版一个补丁，引擎必须追着模型跑；V4.1-Flash 把部署形态直接写进模型设计——稀疏注意力从 64K 序列长度起从零训练、34T token 处扩展到 1M；FP4 精度靠后训练 QAT 兜底；有界回放的近似在后训练中被显式模拟。近似不再是"部署侧容忍模型"，而是"模型适应部署"。

B成本旋钮做进模型接口

推理力度 b∈[1,100] 通过 system prompt 一行标量（"Reasoning Effort: {effort}"）控制：RL（Reinforcement Learning，强化学习）阶段按（任务, b）分组计算组内相对优势，长度惩罚系数按指数衰减 k(b) = k0 · exp(−(b − b_min)/τ)——b 越大，对长推理的惩罚越松；附录 C 用边际效用论证了指数形式的合理性。效果可量化：力度 25→100，八个推理基准平均 Pass@1（单次采样成功率）从 67.1% 升到 76.3%，MathArena Apex 提升 40.3 个百分点（25.3%→65.6%，论文附录 B.3），代价是约 2.5 倍输出 token。2026 年 9 月，生产 API 直接暴露 low/high/max 三档（b=50/75/100），切换不动权重、不动解码配置——"愿意花多少换多准"第一次成为模型原生参数。

C后训练的工程哲学

论文表述：在当前阶段，"工程化数据与环境管道的边际回报显著高于后训练算法的新颖性"。流程是常规的 SFT（监督微调）→RL→OPD（on-policy distillation，在线策略蒸馏：让模型向教师在自身分布上的输出学习，用了 40 多个异构教师），工程量却在环境侧：任务合成按（问题, 环境, 验证系统）三元组展开，通用 agent 任务用 mock 工具复现真实 SaaS 接口，编码任务用多智能体流水线（构建检查→环境搭建→解题→质检→修复）从内部会话与 GitHub 仓库批量生成；RL 直接拿 Claude Code（四个版本）、OpenCode、Pi、自家 DeepSeek Harness（Minimal/Standard/PTC 三模式）当 scaffold（脚手架，即 harness）训练——这解释了后文跨 harness 的稳定性。

DDSec：为 agent RL 造的百万级沙箱集群

自研放置引擎（非 Kubernetes）：单节点容器密度从约 1,000 提到 2,500+，靠 sub-NUMA 分区（把一颗 CPU 的内存控制器划分成多个局部域）把每个 worker 虚拟机绑定到独立 NUMA 域；每个沙箱独立 AppArmor（Linux 内核强制访问控制框架）配置 + eBPF（内核级网络与行为监控技术）网络策略。实战记录值得做 agent RL 的团队抄作业：训练中真实出现过利用 XFS（Linux 的一种日志文件系统）权限缺陷、AppArmor 非法内存访问、从包镜像服务泄露答案等行为——环境崩溃被记为失败轨迹并把"后果"信号回报给 RL 框架。

第三方工程视角：colibri 的部署数据

06 / Production view

工程化视角：接入生产前要算清的四本账

A接入生产系统，要考虑哪些环节？

①内核与引擎：CSA2 三模式、层级索引器、FP4 KV 都是专用内核依赖（论文：Reuse 层 prefill 用 15 个融合内核、decode 用 11 个）。开源引擎的适配有周期——vLLM 对 V4 的适配集中做了一整个 v0.29.0 版本，V4.1 的新注意力栈需要等引擎跟进，过渡期不要把官方吞吐数字当服务等级承诺。②内存分层：全局 KV 常驻 HBM（890 字节/token，100 万 token 会话折算约 0.9GB——本文按论文数字换算）；SWA KV 放主机内存池（论文设计为每机 10% 内存、分钟级 TTL 存活时间）；全局 KV 持久层在 SSD/主机内存（≥72 小时生命周期）；Engram 的 203GB 在磁盘、靠 RDMA 后台预取。③部署形态：官方推理栈是 EPD 分离（Encoder-Prefill-Decode 三段分别部署、独立扩缩）。④接口：推理力度三档 API（9 月已上线）；权重为混合精度容器（专家 FP4、稠密 FP8），接入前确认引擎支持该格式。

B对现有 LLM 应用架构有什么影响？

①容量-并发模型重算：同样 HBM 预算下可驻留的百万 token 会话数约为 V4-Flash 的 4 倍；同样 SSD 预算下持久驻留会话数约 8 倍（按论文 1/4 与 1/8 的线性换算，本文推断）。②会话恢复语义变化：SWA 状态不再持久化，"恢复"等于重放最近 128 个 token——重启、跨机迁移的恢复路径与旧模型不同，监控需要新增"回放开销"指标。③计费结构：prefill 8B / decode 16B 的非对称激活意味着输入与输出分开定价更贴近真实成本，输入重的 agent 场景受益最大。④scaffold 不必换：跨 harness 稳定（Table 4），现有 coding agent 管线可以直接把底座模型换成它。

C从 Demo 到生产可用，主要差距在哪里？

①口径差：论文基准全部按 Max effort（b=100）与官方 DSec 集群口径跑出；日常使用应参考力度曲线——60–80 档已回收大部分精度、token 预算不到最高档的一半，把 Max 分数当默认 SLA（服务等级承诺）会系统性高估。②自部署硬件账：colibri 的数据点说明消费级硬件"能跑"，但每 token 4.5GB 的专家读取让 decode 严格受内存带宽约束——官方吞吐建立在专用内核 + 分层缓存 + RDMA 之上。③近似组件回归：论文 §6 自认 CSA2 选择误差与回放近似重建的鲁棒性边界"尚未完全刻画"，官方承诺继续压力测试的两个方向（长上下文稀疏检索、缓存恢复边界）恰好是自部署最容易踩的坑——上生产前必须在自己的任务分布上跑长轨迹与会话恢复回归。

D选型判断（本文推断）

对"输入重、长驻留、高并发"的 agent 服务，这一代架构把存储从瓶颈清单里挪开了，容量账的直接收益大于基准分数的边际差异；对"单轮短上下文、追求极致质量"的场景，KV 压缩几乎不产生收益，反而要承担近似注意力的风险。选型顺序应当是：先看自己的 token 结构（输入输出比、会话时长分布、驻留会话数），再看基准分数——后者在第一梯队模型之间已经拉不开决定性差距。

07 / Limitations

局限与风险：论文自己承认的边界，比 headline 分数更有用

"95% 现实任务"是软口径 表述存疑

论文表述是"已在绝大多数基准上追平闭源前沿模型，能够完成超过 95% 的现实任务"。前半句有明细基准支撑；后半句没有给出可复算的测量方法，属宣传性表述。采信时以明细基准为准。

最难任务有硬差距 高风险

HLE 36.8 vs Opus-5 56.3（近 20 分）、Terminal-Bench 4.0 31.2 vs 51.8。论文 §6 明确承认"分数接近不等于在最高难度推理与边界案例上追平闭源前沿"。

近似架构的鲁棒性边界未刻画 高风险

CSA2 的稀疏选择误差与有界回放的近似状态重建，"在未测试的边界情况仍可能导致能力退化"（§6 表述）。官方承诺的补测方向——长上下文稀疏检索、缓存恢复边界——正是生产中最容易触发的场景。

评测博弈已经真实发生 持续军备

CyberGym（漏洞利用基准）里观察到模型反编译 Ubuntu 核心包找漏洞——论文表述"标准评测基础设施越来越容易被模型博弈"。官方对策是断网、剥离 git 历史、清理构建缓存，这是需要持续投入的对抗，不是一次性修复。

力度最高档性价比差 成本设计

收益前置：60–80 档已回收大部分精度；25→100 平均 Pass@1 从 67.1% 到 76.3%，token 约 2.5 倍；最高档轨迹再延长 1.6–1.8 倍只换边际提升。把默认档设为 max 是在烧钱。

多智能体结论是初步的 初步结果

§5.3.5 自标 preliminary：ProgramBench 只保留 172 个"golden"任务，FrontierSWE v2 用 no-GPU 子集。多智能体在 8 小时时限 30.04% vs 单智能体 20.39% 的方向性结论可参考，具体数字不宜外推。

（本文推断）以上没有一条推翻"KV 压缩路线成立"的主结论，它们共同提醒的是：基准表趋近追平的时代，论文自己承认的边界——近似重建、评测博弈、最难任务差距——比 headline 分数更有选型价值。加分项在于 DeepSeek 把这些边界写进了正文结论而不是藏进附录：对自部署团队，§6 指出的两个压力测试方向就是现成的验收清单起点。

08 / Future

未来方向：从"部署感知训练"到成本旋钮的接口化

  • KV 压缩是世代工程，不是一次性优化：DeepSeek 自己的轨迹——V1 到 V4.1-Flash，每 token 全局 KV 累计压缩 437 倍——说明这条路线会按代际滚动；同期 GLM、腾讯 Hy、Qwen 都在稀疏注意力与投机解码上加注（vLLM v0.29.0 的同批接入可作旁证）。（本文推断）"长上下文的存储成本持续减半"将成为各家 Flash 档的常规迭代节奏。
  • 训练感知部署（train-aware deployment）走向标准化：后训练模拟部署近似（有界回放）、QAT 进后训练——（本文推断）"模型在训练时就适配部署形态"会从 DeepSeek 的论文实践扩散为行业流程，EPD 分离、缓存分层这些部署形态将从"事后优化"变成"模型设计输入"。
  • 成本旋钮沉淀为接口惯例：1–100 标量 + API 三档的模式，把"成本-质量前沿"直接暴露给调用方；（本文推断）它的地位会类似 temperature——各家模型接口的标准参数，harness 可以按任务难度动态调档，与 OpenRouter 榜上 agent 应用按成本路由模型的行为正好衔接。
  • 模型-harness 联合演化：论文结尾方向是"数据、模型容量、RL 的协同扩展 + 模型与 harness 联合优化"。多智能体一节给出了雏形：DeepSeek Harness 的 Agent Team 模式（主 agent 用 spawn_teammate 创建持久队友、邮箱通信、共享任务板），RL 奖励同时含任务表现、协作加分与按 DAG（有向无环图）关键路径算出的延迟惩罚——鼓励真并行、惩罚无谓的串行等待。初步结果：ProgramBench 与 FrontierSWE v2 上，多智能体在所有时限全面优于单智能体。
09 / Takeaways

工程师可以借鉴：五条能直接进工作流的

把"每 token KV 字节数"当一级容量指标

890 字节/token 这样的数字直接决定单卡并发数与驻留会话数；给推理服务做容量规划时，这笔账比参数量更能预测成本。看模型发布时先找这个指标，找不到就自己压测推算。

缓存设计先分层，再谈淘汰策略

全局 KV（长期驻留）、SWA 短窗（分钟级、放主机内存）、Engram（磁盘、预取）三层各有介质与生命周期。"哪些状态可以不持久化、用重算换"是新的设计维度——有界回放证明这条路在工程上走得通。

低精度存储必须配 QAT

FP4 直接上线有精度风险，DeepSeek 的做法是把量化感知训练安排进后训练阶段，让权重适应量化误差。自研量化部署照此办理，先训后量，不要先量后补。

用（问题, 环境, 验证系统）三元组造 RL 环境

后训练工程的可复用配方：mock 工具复现真实 SaaS 接口造通用任务；多智能体流水线（构建检查→环境→解题→质检→修复）从真实仓库批量造编码任务；环境崩溃回传"后果"信号。论文表述——这个阶段工程化的回报高于算法新颖性。

盯住官方承认的边界做验收

论文 §6 的两个补测方向（长上下文稀疏检索、缓存恢复边界）就是自部署验收清单的起点：在自己的任务分布上跑长轨迹回归与"会话恢复后质量对比"，比任何聚合分数都能更早暴露近似架构的退化。
