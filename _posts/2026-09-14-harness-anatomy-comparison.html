实现对比 · Harness 解剖

四个 Agent 运行时的解剖：同题，四种答案

Claude Code、Codex、DeepSeek Harness、OpenCode 都在干同一件事——把一个模型变成能在你仓库里干活的运行时。但从 agent loop 的第一种写法开始，四家就分了岔：委派用 fork、线程、子会话还是插件注册表？prompt 是拼出来的、服务端下发的、按模型分发的、还是历史里的一条消息？这篇用四家官方文档加一份 83 页的源码解剖论文，把四种工程哲学摆上解剖台。

对比对象：四家 Harness Claude Code · Codex · DeepSeek Harness · OpenCode 主依据：arXiv 2609.00006（源码级研究） 最重一章：多 agent 委派 抓取时间：2026-09
TL;DR

先说结论

如果你只记四件事：

15×
多 agent 的 token 放大倍数
源码研究的设计建议直说：大多数编码任务的真并行度，配不上多 agent 约 15 倍的 token 开销（arXiv 2609.00006，建议 12）。四家都建了委派，但克制程度完全不同。
4 层
Claude Code 的多 agent 谱系
session 内 subagent、并行 session 监控（agent view）、session 团队（agent teams）、模型写脚本的 workflows 四种机制并存——官方对其中三种给出了"谁持有计划"的对比表，是四家中维度最全的。
6 个
DeepSeek Harness 的子代理后端数
它的委派层是"具名提供方注册表"：进程内 spawn / fork、ACP、独立 SDK——外加两个竞品：把 Codex 和 Claude Code 当自己的子 agent 后端跑（DSH 官方文档）。
0 个
400 万行代码里的两个零
11 个生产 harness、约 400 万行 Python/TypeScript/Rust 源码：没有任何一个 import 通用 agent 框架（LangChain、AutoGen、CrewAI……全数缺席），没有任何一个用向量检索读代码。
背景

Harness 是什么，这对比怎么读

H
Agent = 模型 + Harness。2026 年 7 月的源码研究《Harness Engineering》（arXiv 2609.00006，Wavestone AI Lab，83 页）给这个领域下了工作定义：harness 就是模型之外的全部运行时——"the runtime that couples an LLM to the world—its loop, its tools, its context, its safety controls, its orchestration, and its extension surfaces"（推理循环、工具、上下文、安全控制、编排、扩展面）。本站前两篇解读了"怎么测 harness"（Harness-Bench、FrontierHarness 榜单），这一篇回答另一个问题：测的那些东西，里面到底是什么。

该研究把 harness 拆成 7 个子系统，并给出了每一档的极简/极繁实现。这张表是全文的解剖图：

四家与三个口径

对比对象沿用 FrontierHarness 榜单钉死的版本：Claude Code v2.1.237、Codex v0.148.0、DeepSeek Harness v0.1.0-rc.8、OpenCode v1.18.19。但要先交代三件影响读法的事：

口径警告：你读到的每个数字都是"某时点快照"
  1. 源码研究的快照滞后。论文对 Claude Code 的分析基于一份流传的 2026 年 3 月源码快照（它反复提醒发货 binary 可能与快照不同）；Claude Code 官方文档今天描述的部分行为（如 v2.1.257 的模型强制变量）比榜单版本还新。
  2. DeepSeek Harness 是 developer preview。官方 README 明言快速迭代、会有 breaking changes，它的文档随时在变。
  3. 论文语料不含 DSH。研究解剖的 11 个系统（Claude Code、Codex CLI、Gemini CLI、Mistral Vibe、OpenHands、Aider、Mini-SWE-Agent、Hermes、Pi、OpenCode、OpenClaw）里没有 DeepSeek Harness——研究期它还没发布。所以 DSH 的全部细节来自其官方文档，其余三家则可以"官方文档 + 源码研究"双口径互证。
论文自己的话是方法论教训："inventory claims (tool counts, feature cells, version pins) decay in weeks, while structural claims (loop taxonomy, subsystem anatomy, the absences) have so far proven durable"——功能清单级的信息以周为单位过期，结构性结论才耐用（§14.5）。这也是上篇发现 4 讨论的快照过期问题的另一个切面。

下文的引用体系：未特别标注的事实来自四家官方文档（Claude Code = code.claude.com/docs，Codex = learn.chatgpt.com/docs，OpenCode = opencode.ai/docs，DSH = deepseek-harness.github.io）；标"论文"的来自 arXiv 2609.00006；标"DSH 文档"的来自 DeepSeek Harness 官方文档站与仓库。

D1 · Agent Loop

同一个循环，四种跑法

所有 harness 的心脏都是一个 while 循环：调模型、执行工具调用、再调模型。四家的分歧从这么基础的地方就开始了。

Claude Code
SSE 流式 + 智能工具批处理
Anthropic SSE 细粒度流式事件；独特点是工具批处理的并发分类：每个工具默认 isConcurrencySafe = false（安全默认），只有显式声明安全的只读工具（grep/glob/read）才并行，写操作一律串行（论文 §6.2.2）。
Codex
Rust Tokio 异步状态机
Session 编排轮次，经 FuturesOrdered 做有序并行执行，工具运行时已抽出为独立 crate（论文 §6.2.3）。四家中唯一的 Rust 实现，错误恢复策略编译期强约束。
OpenCode
日志即队列（log-as-queue）
字面 while(true)，但消息日志兼作工作队列：待办的子 agent 生成与压缩不是控制流分支，而是持久化的 message parts，循环每轮取一个——跨进程重启天然可恢复。无默认步数上限；三次完全相同的工具调用触发 doom-loop 询问，由用户裁决是不是 bug；上下文溢出从不重试、直接转压缩（论文 §6.2.9）。
DeepSeek Harness
循环本身是插件
官方架构文档明言：agent loop 是"实现 Agent 接口的默认驱动器"，是一个可被配置替换的普通插件。每个步骤先经 pre-step waterfall（可拒绝/改写输入），然后组装 prompt、从日志派生并冻结模型历史再发请求；取消在任何阶段都不落盘（DSH 文档 reference/index）。

一个有用的读法：OpenCode 和 DSH 把"可恢复"当第一公民（一切以日志为中心，DSH 甚至把它升格为运行时不变量，见 D4 节），Claude Code 和 Codex 把"流式性能"当第一公民。这不是谁对谁错，是两种服役环境的取舍。

D6 · 多 agent 委派

重头戏：委派的四种架构

第一层：委派原语怎么造

Claude Code：fork 出去，缓存留下
subagent 用 markdown + YAML frontmatter 定义（项目 .claude/agents/ 或用户 ~/.claude/agents/），每个定义声明：独立上下文窗口、自定义 system prompt、工具白名单、独立权限模式、可选模型。官方明说可以把杂活路由给 Haiku 这类便宜模型。三个硬细节：① 所有 subagent 描述合计超过 15,000 token 会在启动时告警；② spawn 是一次 context fork——论文拆出 6 个维度的克隆（中断控制、文件状态缓存、权限提示、拒绝追踪……），而关键优化是 fork 时把父代理已渲染的 system prompt 逐字冻结传给子代理，保证子代理的请求命中父代理的 prompt 缓存前缀（论文 Table 4 的签名标签："prompt-cache-sharing forks; the reference others copy"）；③ 定义里可加 isolation: worktree，让子代理跑在临时 git 工作树里。官方文档还支持前台/后台两种 spawn，以及按名字 resume 一个子代理。
Codex：一切皆线程
Codex 的委派原语是 agent thread：subagent 拥有自己的线程，用户可用 /agent 命令随时切进某个线程查看（官方文档 subagents 页）。源码研究拆出三件套：中央 AgentControl（spawn 控制面）、AgentRegistry（session 树内全部存活 agent 的元数据）、以及带 fork 模式的 spawn 流程——SpawnAgentForkMode 决定子代理继承多少历史：全量，或只取最近 N 轮，且继承时会过滤消息，只保留 system/developer/user 与最终答案，剔除中间工具调用与推理，防止上下文膨胀。代理间通信用类型化的 InterAgentCommunication 记录（Spawn/Message/Followup/Result）；工具本身有两代（multi_agents 与 multi_agents_v2），按模型元数据选择用哪一代。子代理角色可以用 TOML 文件声明（explorer/worker）——论文称之为"Codex 对 Claude Code agent definitions 的回答"（官方文档 + 论文 §11.3）。
OpenCode：子代理就是子会话
OpenCode 的 subagent 不是独立引擎，而是带 parentID 的 child session，跑同一个 loop（论文 §11.9）。结果以 <task_result> XML 包裹返回，后台完成的结果作为合成 user 消息注入对话。两个反差极大的细节：① containment 不对称——子代理只继承父代理的 deny 规则，allow 不继承；② 递归委派默认关闭（子代理调 task 工具会被自动拒绝），按 agent 定义 opt-in 之后没有数字深度上限。还有一个四家独一份：让 LLM 现场生成 agent 定义（用结构化输出生成 identifier / whenToUse / systemPrompt），不用写配置文件就能"变出"一个子代理。官方文档侧：内置 subagent 有 General、Explore、Scout 等，可用 @ 提及显式点名，也会按描述自动匹配。
DeepSeek Harness：委派是注册表，后端随便换
DSH 的 subagent 是一个 可选能力 seam（DSH 架构术语，指"可替换的能力槽位"：接口声明、实现提供、使用消费三种角色分离，运行时可整体换实现），不属于 agent loop 主干，实现为具名提供方注册表，同一上下文可共存多个后端（DSH 文档 subsystems/subagent）。官方列出六个提供方：进程内 spawn（不继承上下文）、进程内 fork（以父日志已完成轮次的平衡前缀作种子）、ACP（进程外）、codex 后端、claude-code 后端（把两个竞品当子代理，经 subprocess 生成）、独立 dsh SDK 运行时。子代理分两类：one-shot（一次性前台，返回单结果）与 continuable（持久子 Session + 至多一个进程内 Activation，可跑多轮、可冷恢复）；消息只允许直接父子之间，兄弟、隔代、自指一律拒绝。请求可携带 outputSchema（强制 JSON 结构化输出）、maxDepth（委派深度上限）、toolFilter（对子代理的工具可见性过滤——文档强调这是"可见性而非权限"，被过滤的工具从 prompt 消失且拒绝执行）。能力不匹配的请求返回 UNSUPPORTED_CAPABILITY，"fail loud, no silent degradation"。

第二层：编排——"谁持有计划"的四种回答

单次委派之上，谁去编排几十个 agent？四家给出了四个方向不同的回答：

Claude Code：模型写 JavaScript
Workflows 机制：Claude 写一段 JS 脚本（agent()、parallel()、pipeline()、phase()、log()），runtime 在后台执行它、主 session 保持响应。硬上限：16 个并发、单次运行 1000 个 agent、单条 pipeline 4096 项。最精妙的是扇出时的缓存经济学：第一个 agent 先跑，其余 agent 读它焐热的缓存前缀，间隔 5 秒错峰启动——把 prompt caching 直接编进了编排语义。脚本可保存为斜杠命令分发、可恢复（官方文档 workflows 页）。
DeepSeek Harness：同构，且承认对齐
DSH 的 workflow 工具让模型运行"会启动 subagent 的编排脚本"：script（纯 JS 函数体）、meta、args。引擎跑在 node:worker_threads 的 vm 上下文里，提供 parallel()/pipeline() 组合器与 maxTotalAgents 总量上限。两个特色：meta 块的字段词汇官方文档注明与 Claude Code 动态工作流的 meta 块一致；失败纪律是"拼错的选项必须 fatal 报错，绝不静默消融成普通失败"（DSH 文档 subsystems/workflow）。另有内置的 ralph 工具（固定前台工作流，每轮启动一个全新结构化子级，即 Ralph 循环模式）。
Codex：不写脚本，写数据
Codex 的答案不是自由编排脚本，而是结构化批量扇出：spawn_agents_on_csv 对每一行 CSV 生成一个子代理，共享一个 JSON Schema 结果契约，带并发上限与结果回收（论文 §11.3）。委派本身受模型治理：新的 ultra 推理档在模型目录里的描述是"maximum reasoning with automatic sub-agent task delegation"——论文指出这是全部语料中唯一改变编排行为的 effort 档；本地 Codex 文档则说明触发条件是用户直接要求，或 AGENTS.md / skill 指令请求。
OpenCode：不给编排层
OpenCode 的多 agent 全部 = task 工具 + child session 树 + 快捷键导航（child_first/child_cycle/parent 在会话树里移动）。没有 workflow 引擎、没有团队、没有扇出原语。这是设计选择而不是缺失——它的定位是轻量中立客户端，把重编排让位给上层。

第三层：团队——lead、teammates 与任务板

"Agent team"是用户感知最强的一层。四家的现状：

Claude Code Agent Teams：机制最完整，但官方自己先泼冷水
  1. 结构：一个 lead session（你正在对话的这个）spawn 出多个 teammates，每个是完全独立的 Claude Code session——加载自己的 CLAUDE.md、MCP 与 skills，但不继承 lead 的对话历史。四件套：lead、teammates、共享任务列表、mailbox（实为磁盘上的 JSON 文件：~/.claude/teams/{team-name}/inboxes/{agent-name}.json）。
  2. 任务板：任务三态（pending / in progress / completed）+ 依赖关系；lead 完成被依赖任务后自动解锁下游；多代理抢单用文件锁防竞争。
  3. 权限纪律：teammate 继承 lead 的权限模式（dontAsk 模式除外）；teammate 的权限提示冒泡到 lead 由你批；teammate 不能替另一个 teammate 批权限，被拒的动作也不能通过别的 teammate 中继绕过检查。
  4. 质量门：TeammateIdle / TaskCreated / TaskCompleted 三个 hook 可用 exit code 2 拦截并给反馈。
  5. 硬限制（官方 Limitations 节）：实验性、默认关闭（需设 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1）；无嵌套团队；一个 session 只有一个 team；lead 固定不可转移；in-process teammate 不能再开后台 subagent；/resume 不恢复 teammates。
  6. 官方定位：启用前先问"更轻的选项够不够"——subagent 在单 session 内就能干，cross-session messaging 能在你自己开的多个 session 之间传话。
code.claude.com/docs/en/agent-teams（v2.1.178 起免 setup 步骤；细节大量随小版本变动，读原文为准）。
DeepSeek Harness 的团队层
同样标实验、默认禁用（dsh-base 里关着，官方提供 profile patch 启用）。工具面 9 个：spawn_teammate、send_message、wait_agent、interrupt_agent、list_agents、team_task_* 四件。两个更精细的物件：任务板是 compare-and-swap（revision 递增）+ blockedBy 维护无环 DAG；每个任务的 writeScopes 是"提示性路径前缀"，官方文档直接注明"不是锁"（DSH 文档 subsystems/agent-team）。
Codex 与 OpenCode：用别的原语替代团队
Codex 没有常驻团队，它的"多实例并行"答案是产品化的 git worktrees：每个 chat 可跑在独立 worktree（$CODEX_HOME/worktrees、detached HEAD、默认保留 15 个），Handoff 命令把 chat 在本地与 worktree 之间搬（官方文档 git-worktrees 页）。OpenCode 的答案是用户自己多开 session。两家都把"协调"留给人类。

第三层半：不开实验开关的轻量并行

顺带补齐 Claude Code 谱系里不需要任何实验开关的两个机制：agent view 让你自己并行开多个 Claude Code session，在一块面板里监控全部会话的状态、收割结果；cross-session messaging 让你自己开的多个 session 之间互相传话。官方把这两个机制列在 agent teams 之前，作为启用团队前"先看看更轻的选项够不够"的推荐路径——它们的定位是人来驱动并行，而不是 agent 自动协调。

第四层：成本与模型路由

多 agent 的账单问题，四家的态度差异极大：

Claude Code
把缓存经济学贯彻到委派：fork 冻结 system prompt 保缓存命中；官方文档明确 subagent 可路由给 Haiku 省钱；in-process teammate 的请求落在独立的缓存 TTL 桶（默认 5 分钟，可用 subagentPromptCacheTtl 调到 1 小时，代价是更贵的缓存写入价）。官方 agent teams 页多处明确警告"token 显著更多"。
Codex
模型路由写进产品语义：内置 subagent 用不同模型干不同活（worker 执行、explorer 只读探索）；多代理工具按模型选代；委派密度由推理档治理（ultra=自动委派）。
OpenCode
官方文档：subagent 默认继承调用它的 primary agent 的模型。没有便宜模型路由——省 token 的方式就是少委派。
DeepSeek Harness
SubagentStartRequest 可按请求覆盖提供方/模型/推理强度/token 上限（agentOptions），并提供 list_subagent_models 工具做模型发现。路由自由度四家最高。
给"多 agent 焦虑"的一盆冷水

源码研究的设计建议 12 原文值得抄录："保持单 agent，直到你能指出一个具体的广度优先探索阶段、并行上下文隔离明确胜过串行搜索"——因为多 agent 约多耗 15 倍 token（论文特意注明：这个 15 倍的对比基准是单次 chat 对话，不是优化过的单 agent 管线），而"most coding tasks involve fewer truly parallelizable tasks than research"（大多数编码任务的真实可并行段，比调研类任务少得多）。研究同时观察到 coordinator-worker 架构在多家独立涌现（观察 7）——涌现说明它有用，但四家的优化目标各不相同：Claude Code 优化成本，Codex 优化隔离与规模。判断你的场景到底有没有真并行段，比选哪家 harness 更重要。

第五层：跨 harness 委派——最有想象力的一步

回到上面谱系表最后一行。DSH 的六后端里有两个竞品后端（dsh-subagent-codex 与 dsh-subagent-claude-code），设计决策有专门的设计记录（仓库 .agents/notes/ 内 2026-08-04 的 Agent Note）。这件事的意义是：委派层的抽象一旦做对，吃掉的不只是模型层，还有别家整个 harness 的生态位——DSH 用户可以在一个会话里把"探索仓库"派给 Codex、"安全审查"派给 Claude Code，各自带着自己家的工具链和 prompt。

协议层的背景同样重要。论文观察到 ACP（Agent Client Protocol）已进入 6/11 个系统，并长出了设计者没预料的第二个角色：harness hosting——OpenHands 通过 ACP 把 Claude Code、Codex、Gemini CLI 当作可互换的"大脑"接进自己的对话（论文金句："The protocol built for editors turned out to be the interface for hosting"）。但同时，9 个有多 agent 能力的系统里 8 个的自家 subagent 仍是进程内原语，跨进程的也绕开标准协议（Pi 用私有 JSONL，Hermes 用 SQLite 黑板）；唯一把子代理协调走标准协议的是 OpenClaw。论文给出的工程指导是：对外发布 ACP server（一次吃到 IDE、host、meta-orchestrator 三类消费者），对内 subagent 保持 in-process——委派的护城河在 fork 隔离、缓存共享、权限冒泡这些进程内细节，不在协议（§13.3）。

D2 · Prompt 动态组装

四种拼法，一个问题：哪些字节进缓存前缀

prompt 组装表面上是字符串拼接，实际是在回答一个工程问题：每次请求里，哪些部分保持稳定（吃 prompt 缓存），哪些必须逐轮变化。四家的答案完全是四条路。

Claude Code：静态/动态边界
system prompt 由 12–15 个命名 section 组成，以 SYSTEM_PROMPT_DYNAMIC_BOUNDARY 标记一分为二：边界之前（身份、系统规则、任务指引、工具模式、语气）是静态区，做 Blake2b 哈希跨 session 缓存；边界之后（会话指引、memory、环境、MCP 指令、语言、scratchpad）是动态区，按轮计算并 memoize（论文 §7.2.3）。配合 fork 冻结继承，缓存边界贯穿了它整个产品。
Codex：prompt 是服务端数据
Codex 走得最远：prompt 不在代码里。operative prompt 是 model manifest（models.json，本地兜底 + 远端 /models 端点 + ETag 缓存）里的 base_instructions 字段，按模型代际下发，还带 {{ personality }} 模板变量。论文测出了内容漂移：GPT-5.2 的 prompt 开头是"You are GPT-5.2 running in the Codex CLI…"，GPT-5.5 缩为"You are Codex, a coding agent based on GPT-5…"，5.6 再缩为"You are Codex, an agent based on GPT-5"，并删掉了 no-commit 规则与全部防镀金指令——原来写在 prompt 里的行为策略，改成了 codex_git_commit 这类 feature flag（论文 §7.2.4）。
OpenCode：按模型家族发九份 prompt
OpenCode 按 model-id 子串派发 9 份 base prompt——给 Claude 系模型的开头是"You are OpenCode, the best coding agent on the planet."。system prompt 刻意压到最多两条 message 以匹配缓存槽；同时把 6 种 prompt-cache 方言同时发射给不同提供方（cache-dialect fanout 模式）。底层委托 Vercel AI SDK——论文注明这是全部语料中唯一内层用第三方 SDK 的系统，自研 client 藏在 flag 后待命（论文 §7.2.8）。
DeepSeek Harness：prompt 是历史里的一条消息
DSH 的组装面分四类注册：section（静态或动态文本）、context（运行时上下文）、tools provider（每次组装评估可见工具 schema）、variable。最独特的设计（有 2026-09-02 的设计记录）：系统提示词以 system/message 节点而非请求字段到达模型——首步追加为 surface 第 0 号节点，渲染文本变化时原地替换，对 KV cache 前缀友好且完全可从日志重建（DSH 文档 subsystems/system-prompt）。

AGENTS.md：四家全吃的指令文件

prompt 组装里有一块事实标准已经收敛：项目指令文件。四家的吃法：

Harness指令文件机制
Codex原生主场：全局（~/.codex，AGENTS.override.md 优先）→ 项目根到当前目录逐层拼接（每目录至多一个文件，越近越后、后出覆盖），总量默认上限 32 KiB，支持 fallback 文件名列表，每次启动重建无缓存（官方文档 agents-md 页）

D3 · 工具系统

Function calling：数量、加载与编辑契约

工具系统是 harness 与模型之间的接口面。三个子问题拆开看：给模型看多少工具、怎么给、怎么改文件。

工具面有多大
Claude Code：43 个类型化工具（论文对 3 月快照统计）。Codex：25–30 个（论文）。OpenCode：官方文档列 13 个内置（bash/edit/write/read/grep/glob/lsp/apply_patch/skill/todowrite/webfetch/websearch/question——lsp 需实验开关，另加 task 委派与 3 个隐藏系统 agent；论文按 first-party 口径计 17 个）。DSH：默认启用约 30 余个（全表另有选择启用的 terminal、会话查询、agent-team、cordis 七件套等）；目录由脚本真实启动每个工具插件读 schema 生成，CI 保证不缺文档。
按需加载
工具多了 prompt 就爆。Claude Code 是 deferred loading 的发明者：标记 shouldDefer 的工具不进初始 prompt，模型用工具搜索工具按需发现，初始 prompt 约缩 40%；Codex 独立收敛出同款（BM25 词法索引驱动的 tool_search）——论文视之为"竞争特色的半衰期以周计"的证据（观察 + §14.5）。OpenCode 13 个工具不需要；DSH 用 tools provider 每次组装时评估，并区分"拼写错误"与"有意隐藏"。
并发怎么切
Claude Code：isConcurrencySafe 默认 false，安全默认、显式声明才并行。DSH：只有精确为 true 才进并行组，其余形成排序屏障（exclusive）。两家不同代码库给出的答案几乎逐字相同——独立趋同。
OpenCode 的按模型换面板
OpenCode 会按模型族换工具集：GPT 系拿到 Codex 式的 apply_patch 工具，同时完全失去字符串替换编辑工具（论文 §8.3）——工具面板本身是模型条件的函数。

D4 · 记忆与上下文

上下文压缩：循环里的，和循环外的

上下文快满时怎么办、跨会话记什么，是 2026 年上下文工程的两条战线。论文的判断：压缩设计已经收敛，真正的分化点在记忆的写路径（观察 5）。

Harness触发摘要策略独有细节
Claude Code有效窗口下方 13,000 token 缓冲即触发剥离图片→按轮分组→LLM 生成摘要→SystemCompactBoundary 分隔压缩后有 50,000 token 恢复预算（最多重读 5 个文件）；skills 截到每 skill 25K（论文 §9.5）
Codextoken limit 双路触发（本地端点 + model_auto_compact_token_limit）摘要压缩rollout token budget 余量提醒、耗尽即中止——预算是一等公民（论文 §9.5/9.6）
OpenCodechars÷4 估算（全代码树无 tokenizer），输入额度减预留输出触发增量合并：把前一份摘要装进 previous-summary 块，回传给一个隐藏的、全工具拒绝的 compaction agent 合并（"保留仍真实的，删除过时的"），输出强制五段 Markdown 结构保留最近 2 条用户消息原文；剪枝只在可回收 >20K 且保护最近 40K 时触发；每项目 shadow git 仓库 逐步快照，支持"会话+文件系统"整体回滚（论文 §9.5）

论文 §9.5（触发参数、OpenCode 增量摘要、shadow git）；DSH 文档 subsystems/compaction、subsystems/spill。

真正的分水岭：记忆由谁维护

M
Codex 是全部语料中第一个"长期记忆由 agent 而非代码维护"的系统（论文 §9.6 原话："the first system in the corpus whose long-term memory is maintained by an agent rather than by code"）。它的记忆管线是后台两阶段：先把每个 rollout 的内容用 LLM 抽取进 SQLite（带租约任务、重试退避、密钥脱敏），再由一个沙箱化的内部 subagent（无审批、无网络、只本地写）审阅工作区 diff，把值得记的整合进 git 管理的 ~/.codex/memories/；新会话注入记忆时带引用追踪与使用度排序。

其余三家的记忆姿态：Claude Code 是 CLAUDE.md 三层 scope + 自动记忆目录（写路径由约定治理）；OpenCode 干脆没有持久记忆治理——它的持久化就是会话底座本身（可恢复、可查询），加上 AGENTS.md 这类上下文文件约定；DSH 的方向是"会话引用"——在对话里提及另一个会话，其有界只读快照即成为上下文，另有记忆 MCP 插件。论文观察到四种记忆写路径治理模型正在分化：agent 维护（Codex）、人类审批（Gemini CLI 的 patch inbox）、模型直写但有界（Hermes 的字符上限快照；OpenHands、Claude Code 的上下文文件约定）、回合前主动召回（OpenClaw）——并且 11 家没有一个用 embedding 做主记忆底座，生产上限是 SQLite 全文检索（观察 5）。

DSH 的运行时不变量："模型可见即已记录"

DSH 把上下文工程做成了可断言的不变量：抵达模型请求的一切都必须能从会话日志重建（Model-visible ⟺ logged），由运行时断言强制；日志 append-only、分代迁移（vN→vN+1 各一个迁移包，已提交代绝不重写），配 SQLite 全文检索与投影缓存。压缩、fork、会话引用全部建立在这一层之上——这是把 OpenCode 的"日志即队列"推到了逻辑终点。

D5 · 安全与权限

权限与沙箱：四种安全观

安全是各家投入差距最大的子系统——论文观察 6 的结论：OS 级沙箱是语料中代码最昂贵的能力之一，且"是选择而非规模的结果"（最大的系统未必有沙箱，见 OpenCode）。

Claude CodeCodexOpenCodeDeepSeek Harness
审批链三层：静态 hook 规则（最快）→ LLM 权限分类器（allow/ask/deny）→ 用户对话框（最可靠）四层：Starlark 执行 policy → 生命周期 hooks → Guardian 审批 agent → 原生 OS 沙箱默认极少询问：项目内全放行，只对外部目录访问、.env 读取、doom loop 询问工具流水线的 ask 瀑布 + fail-closed 审批（结果类型封闭，异常一律按拒绝）
命令粒度hook 对 PreToolUse 做 pattern 匹配prefix_rule / network_rule，规则可携带解析时校验的测试样例（"策略文件里的可执行测试用例"）语法感知：每条 bash 命令用 tree-sitter 解析，"always allow"按参数元数（arity）限定——产出 git commit * 式授权而非全量放行消费方交出精确 argv，沙箱包装后返回带"拒比方言"（bwrap 的 EROFS / Landlock 的 EACCES / Seatbelt 的 EPERM）的受限命令
OS 沙箱opt-in（沙箱运行时 + worktree）三平台原生：Linux vendored Bubblewrap（只读根+断网）、macOS Seatbelt、Windows 受限令牌+ACL无（代码里的"sandbox"实际是 git worktrees）三平台 seam：与 Codex 同款后端清单（bwrap/Landlock、Seatbelt、Windows ACL 受限令牌），无后端即抛错，"受限策略下静默透传永远不合法"
哲学一句话纵深防御，越快越糙、越慢越准policy 是代码，审批也是 agent（Guardian 超时或输出畸形即 fail-closed，带拒绝熔断）信任默认 + 语法换粒度（v2 已反转为 deny-by-default）一切 fail-closed；凭据只存引用、UI 只见脱敏描述符；SAFETY.md 明言未经安全审计、不得视为生产就绪，且不得作为不可信工作负载的唯一安全控制
论文 §10（CC 三层、Codex 四层、OpenCode 语法感知与 arity 字典——约 130 条 LLM 生成的命令元数字典、last-match-wins 规则链）；DSH 文档 subsystems/sandbox、subsystems/approval、SAFETY.md。
最优雅 vs 最重
论文称 Claude Code 的三层是"the most architecturally elegant safety system"；同时点出关键限制：后台/forked subagent 只有前两层，它的权限提示一律按拒绝处理，未决情形升级回父协调者。每个 async agent 维护独立的拒绝状态，防止跨 agent 污染。
OpenCode 的"工具可见性即权限"
OpenCode 对某工具 deny "*" 的效果是把该工具从模型视野整个移除——工具可见性本身就是权限的导数（论文 §10.9）。配合"plan mode = 一组权限规则 + system-reminder 注入而非架构叠加"（§11.9），它的权限系统是语法问题，不是隔离问题。

Claude Code 的插件清单格式被 Codex 与 OpenHands 双双采纳（后者 loader 直接接受 .claude-plugin 扩展名——论文称之为"语料中最清晰的互操作-by-采纳案例"）。
1 份 importer
Codex 为竞品写的迁移器
Codex 内置第一方 importer：检测 ~/.claude/projects 的会话 JSONL 转成自己的 rollout，并提议把 ~/.claude/settings.json 翻译成 config.toml（论文 §14.3）。迁移成本被做成了产品功能。
2 个 wire 库
DSH 的兼容桥
DSH 的 hooks 包组提供 Claude Code / Codex hook 桥与共享 wire 协议库；skills 六级发现目录里含竞品主目录；仓库自己的 CLAUDE.md 是 AGENTS.md 的 symlink——它把兼容做成了架构决策。
"Convergence became imitation"——四月的趋同是各自发现，七月的趋同是可溯源的模仿

论文纵向对比了 8 个系统一个季度的源码演化（§14.5），最有说服力的证据链：

  1. Codex 的 hooks 事件词表近乎逐字来自 Claude Code（PreToolUse/PostToolUse/PreCompact……外加一个 CC 没有的 PostCompact）；
  2. OpenCode 的 skills 目录刻意搜索竞品主目录（~/.claude/skills），官方文档明说"为 Claude Code 装的 skills 在 OpenCode 原样可用"；
  3. OpenHands 采纳 CC 的插件格式、任务工具签名、静态/动态缓存边界；
  4. Hermes 在源码注释里公开致谢 OpenCode（编辑匹配）、Codex（智能审批）、OpenClaw（编排 prompt）——"Cross-harness lineage is now written in the code itself"；
  5. 以及上文那枚 Codex 写的 CC importer。

"竞争特色的半衰期目前以周为单位。"（§14.5）——这意味着功能清单上的差异比看起来更短命，下面的理念画像比上面的功能表格更保值。

四家的扩展哲学

Claude Code
hooks 是主导扩展面（4 月还是它独有）；skills + agent 定义 + MCP。它的输出物（hook 词表、.claude-plugin 格式）成了行业接口——这就是"参考系"的含义。
Codex
marketplace 插件管线（GitHub/git/URL 来源 + 模型可调用的 request_plugin_install 会话内审批工具）+ skills 的隐式触发识别 + 配置栈向上延伸到 MDM/企业托管——论文称"语料中最企业治理导向的配置模型"。
OpenCode
插件 ≈ 约 20 个类型化 hook 点的 async 函数，顺序执行保确定性；自定义工具零插件——.opencode/tool/*.ts 任意导出即成；外加 ACP server（opencode acp）。
DeepSeek Harness
扩展不是机制，是范式：一切皆插件（含 loop、含 system-prompt 组装器），Cordis 保证"注册即副作用、卸载即撤销"；运行实例 = profile → bundle → patch 层叠出来的插件树，树上任何条目都能被自己的 patch 替换（dump-config 可打印全树）。连它的桌面应用（Electron）都不开端口，走 dsh-app:// 协议。
横向发现

两个零、一次平台化转身

Twin Absences：400 万行代码里的两个反直觉的零

论文最被引用的发现（§13.2）：把 11 个系统的依赖清单全部检查、对全部源码树 grep 框架名——LangChain、LangGraph、LlamaIndex、AutoGen、CrewAI、Pydantic AI、Genkit、Haystack、Semantic Kernel、Google ADK、Smolagents、Swarm、Agno——零命中。几个注脚很有味道：

连自家的都不用
Gemini CLI 不用 Google 自家的 Genkit 与 ADK。作者写明："我们预期至少能找到一些使用……寻找反例（vendored 依赖、动态 import、转译产物）花了几周才接受结果。"
两个"差点算"的例外
Hermes 树里仅有的 "LangChain" 字符串在打包的 skill 文档里（教用户怎么用向量库）；OpenCode 的 Vercel AI SDK 是 provider 抽象层而非编排框架——唯一内层用第三方 SDK 的系统，且自研替代 client 藏在 flag 后。
第二个零：代码不用向量检索
向量库/embedding 关键词全语料零命中（检索代码这件事）。替代方案：ripgrep、glob、tree-sitter、LSP。唯一 embedding 默认开启的是 OpenClaw 的记忆插件——且只用于聊天召回，从不用于读源码树；Hermes 反着选：会话检索刻意词法化（SQLite FTS5），"no LLM calls anywhere"。
为什么
论文给的三条：代码有稠密的确定性结构元数据（路径、LSP、类型），语义相似检索复制不了；代码分钟级变化使预索引过期；每个编码环境自带近最优检索（ripgrep/find）。结论句："Production harnesses operate on a different complexity budget from generic LLM applications."

从工具到平台：竞争单位变了

论文的主线论点：2026 上半年，coding harness 完成了从 tool 到 platform 的转向。证据俯拾即是：每家都发了 SDK（Claude Agent SDK、Codex SDK、OpenCode SDK——前三者见论文 §14.2；DSH 甚至有 Python SDK，打包原生运行时 wheel，普通运行连系统 Node.js 都不需要，DSH 文档）；marketplace 与企业托管配置（MDM）齐备；出现了 Omnigent 这样的 meta-harness——从上层编排 11 家厂商 harness、"自己不实现任何编辑循环"；甚至有系统冒充第一方 harness 身份去骑乘其订阅后端（论文列的 Harness Mimicry 模式）。结论句值得原样抄录："The competitive unit of the field is no longer the agent loop; it is the ecosystem surface around it."

地板有多低：90 行的最小可行 harness

论文附了一个约 90 行 Python 的 minimum-viable-harness（§16.10）：一个 Model 协议、四个工具（bash/read/write/search_replace，替换唯一性校验）、从根到叶的 AGENTS.md 发现、阈值压缩（保留尾部 30% 原文）、成本与步数上限。它直接实现了 18 条设计建议中的 10 条，作者猜想它跑前沿模型可以追平 Mini-SWE-Agent 的 SWE-bench 数字——"the floor is low"。生产系统与地板的差距不在能不能过题，而在安全、恢复、成本治理与平台面——这也解释了为什么本篇前面那些"多余"的子系统全都值钱。

理念画像

四家的一句话画像

功能会互相抄（以周为单位），设计重心不会。把前文全部收进四张卡片——注意这是"设计重心归纳"，不是能力高下。

Claude Code · 被模仿的参考系
"the reference others copy"
缓存经济学贯穿一切（静态边界、fork 冻结、独立 TTL 桶）；多 agent 谱系四家最全（subagent → view → teams → workflows）；hooks 词表与插件格式输出成了行业接口。哲学：把多 agent 做成缓存友好的经济学。
Codex · 平台与企业治理
prompt 下发、policy 代码化
prompt 是服务端数据、行为策略放配置不放 prompt（no-commit → feature flag）；四层安全 + 三平台原生沙箱；marketplace + MDM 企业栈最重；第一个 agent 自维护记忆；effort 档直接控制委派密度。哲学：harness 是平台，治理在配置层。
OpenCode · 提供商中立派
多提供商是产品核心
Vercel AI SDK + 1400 行 per-vendor 变换矩阵 + 9 份按模型家族的 prompt + 6 种缓存方言同时发射；client/server 架构（论文注：约五分之三代码是客户端而非 harness 本体）；权限做成语法问题（tree-sitter + arity 字典），零 OS 沙箱；生态直接吃竞品格式。哲学：把中立做成功能，把权限做成语法。
DeepSeek Harness · 形式化激进派
Everything is a Plugin
Cordis 演算落地（temporal + spatial composability，arXiv 2608.25512）：卸载即撤销是运行时保证；一切皆插件（loop 也是）；委派层是六后端注册表、直接吃下两个竞品当子代理；"模型可见即已记录"不变量 + prompt 即消息；Windows 一等公民（pwsh 逐项对应 bash）+ Web-first + Agent Note 设计记录制度。哲学：插件化不是扩展机制，是编程范式。
落点

给初级 AI 工程师的六条

想自己攒 agent：从 90 行开始，别用框架。11 个生产 harness、400 万行代码，零框架依赖不是巧合——手写 async loop 才是主流。要"全家桶"就直接用 harness SDK（Claude Agent SDK、Codex SDK 等），不要用编排框架拼。
别为代码建向量检索。ripgrep + glob + tree-sitter/LSP 就是生产答案；embedding 只在会话记忆里有先例。RAG 的收益在代码场景高度存疑，而维护成本以分钟为半衰期。
工具面：先一个 bash，超 15 个再做按需加载。CC 与 Codex 在互不知情的情况下独立收敛出同款方案，这个阈值可以当经验法则。编辑契约跟模型档位匹配：前沿模型用精确唯一子串，弱模型配模糊级联。
压缩：固定缓冲阈值 + 保留原文尾巴 + 增量合并。不要每次从头重新摘要——把旧摘要喂回合并（OpenCode 模式）。预算进恢复：压缩后给文件重读预算（Claude Code 的 50K）比省那点 token 值。
多 agent：先证明有真并行段，再谈架构。约 15× token 是入场费。一条务实的升级路径是：单次委派 → 可恢复子代理 → 脚本编排 → 常驻团队。团队层目前两家都标"实验、默认关"——这不是谦虚，是 token 账单和协调开销的诚实。
选型看哲学，不看功能清单。深度绑定单厂生态 → Claude Code / Codex；多提供商中立 + 轻量 → OpenCode；要"一切可替换"、Windows 一等公民、或想把别家 harness 当子代理调度 → DeepSeek Harness；企业治理与审计 → Codex 的 MDM 栈目前最重。功能会以周为单位被抄走，哲学以年为单位不变。
