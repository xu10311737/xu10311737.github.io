把复杂 Skill，交还给状态机

当 Agent Skill 越来越大、分支越来越多，手写 Prompt 再也撑不住确定性流程时——一个叫 fsm-to-skill 的项目给出了另一条路：让大模型回归「推理」本职，把「流程控制」交还给经典而严谨的有限状态机（FSM）。

完全本地 7 种节点 真实 LLM 调试 一键导出标准 Skill
01 · The Problem

复杂 Skill 的痛点，出在哪里？

一个 Skill 一旦从「几句提示词」长成「成百上千行的多步流程」，问题会以四种方式集中爆发。

01

流程失控与幻觉

复杂 Skill 挤满了分支判断和流程约束。冗余与冲突的描述越多，AI 越改越费力——Skill 越庞大，越容易诱发奖励黑客行为与逻辑幻觉。

02

维护成本爆炸

复杂 Skill 没有清晰的逻辑边界。业务一变更，面对上千行 Prompt 无从下手；AI 越改越费力，Skill 越改越庞大，陷入恶性循环。

03

关键约束被遗忘

执行链路一长，LLM 注意力就会分散，重要约束被忽略。比如要求逐个执行 100 个相似但复杂的任务时，模型常遗漏约束或跳过步骤。

04

经验无法沉淀

复杂推理流程散落在多次手写 Prompt 里，难以复用、难以组合，也难以沉淀为可分享、可版本化的 Skill 资产。

02 · The Idea

思路：让流程是流程，让推理是推理

核心主张——让大模型回归「推理」本职，把「流程控制」交还给经典而严谨的有限状态机（FSM）。
  • 用 DAG 显式建模确定性流程分支、循环、汇聚、多出口，全部用有向无环图（DAG）画出来，流程即数据，看得见、摸得着。
  • LLM 只负责「单步推理」模型在节点内做判断与产出，而「接下来走哪条边」由状态机决定——确定性握在工程手里。
  • 可校验、可追溯、可版本化无环、单开始、变量可追溯、类型匹配、禁嵌套 For……结构问题在导出的第一时间被拦住，而不是运行时才暴露。
    • 03 · How It Works

    如何实现：编排 → 调试 → 导出

    整个工具完全本地运行：纯前端画布 + Python 后端引擎。三步走，把确定性的流程变成可被任意 Agent 加载的标准 Skill。

    1

    可视化编排

    在画布上拖拽节点、建立连线，构建你的 DAG。7 种节点覆盖编排所需的基本能力：

    start→ code→ llm→ if→ for→ end
    start 入口声明变量code 子进程执行llm 渲染 Prompt if 条件分支for 循环迭代aggregate 汇聚end 终止
    2

    真实 LLM 调试

    接入真实 Agent 在线运行：流式输出、Token 统计、节点级变量快照、四色状态标识（运行中 / 成功 / 失败 / 跳过），Code 节点还能单独注入参数验证脚本逻辑。调试透明，不再「不知道在哪一步跑偏」。

    3

    一键导出标准 Skill

    校验通过后选择目录导出，得到可被任何支持命令行交互的 Agent 加载的 Skill 目录：

    SKILL.mdagent_interface.jsonworkflow.yaml inference/scripts/

    其中 scripts/main.py 是自包含的状态机入口：每个 Code 节点是 Agent 输入进入 DAG 的入口，每个 Prompt（llm）节点是 DAG 返回 Agent 的出口，任务状态按 task-id 持久化到磁盘——Agent 只需一条命令即可进入流程。

    python main.py --task-id task-001 --step-id code-1 --step-param '{"arg-1":"hello"}'
    04 · Vs. Flow to Skill

    与 Flow to Skill 的核心区别

    Flow to Skill 是一个 VS Code / Cursor 扩展：用可视化流程图编排，保存为 YAML，再交给 Cursor 的 Agent 聊天面板生成 SKILL.md 与配套脚本。两者都试图「把 Skill 创作从手写里解放出来」，但哲学不同。

    维度Flow to Skillfsm-to-skill
    定位 可视化辅助生成工具，偏「编辑 + 导出」 引擎编排 + 运行时的完整工具链
    生成方式 把 YAML 交给 LLM 理解后生成脚本（黑盒、非确定） 把 DAG/FSM 确定性编译成可执行 Skill（白盒、可预测）
    流程控制权 执行逻辑由 LLM 临场决定，存在幻觉 / 遗漏风险 流程由状态机显式决定，LLM 只做单步推理
    运行形态 导出依赖宿主（Cursor Chat）与 LLM 生成管线 自带可执行状态机运行时，独立可运行，Agent 一条命令即可进入
    可信度 / 可调性 一次性生成，生成前仅做结构校验 29 项结构校验 + 真实 LLM 节点调试 + 变量快照 + 错误定位
    资产沉淀 流程以 YAML 保存，执行逻辑依赖 LLM 转译 流程即数据（DAG），可校验、可追溯、可版本化、可复用组合

    一句话：Flow to Skill 让 LLM 帮你「写」Skill，fsm-to-skill 让状态机替你「保证」流程。

    流程是流程，推理是推理。

    当你的 Agent 需要「多步、可分支、可循环、可计算」的确定性能力，却不想手写状态机、也不想让大模型在关键路径上自由发挥时——fsm-to-skill 把两者都接住了：用可视化把事情画清楚，用状态机把流程跑稳，把大模型的聪明留在该用的地方。
